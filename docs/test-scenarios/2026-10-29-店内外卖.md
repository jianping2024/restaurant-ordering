# 店内外卖 — 业务场景测试

日期：2026-10-29  
分支：`feat/instore-takeaway-impl`  
关联：`docs/instore-takeaway.zh.md`  
UAT 基址：`http://localhost:3003`（feature 分支，非 `:3000`）

## 本次修改

- 总开关 `takeaway_ordering`（默认关；关前检查外卖组未结账桌）
- 桌位分组 `is_takeaway`（全店唯一）；看板开启时外卖组贴在「同行组」左侧
- 菜品销售方式：`takeaway_role` + `takeaway_price`
- 开台写入 `table_sessions.ordering_channel`（唯一判定：`resolveTableOrderingChannel`）
- 外卖菜单/加单价：catalog + `resolveAppendCartItems`
- 外卖开台 API（无人数/套餐）；堂食打包费在外卖会话隐藏并接口拒绝
- 外卖耗材结账：API `checkout/packaging` + 结账底栏「＋ 外卖耗材」弹窗（`CheckoutPackagingModal`）
- 转台同渠道 SQL；并台跨渠道 trigger 拒绝
- 营收：今日卡 / 区间营业额在总开关开时按堂食·外卖分段（`revenueByOrderingChannel`）；日统计写 `dine_in_revenue` / `takeaway_revenue`

## 核心业务规则

1. 有会话 → 只认会话 `ordering_channel`；无会话 → 总开关开且桌在外卖组才为外卖
2. 外卖耗材永不进点餐菜单；点餐接口拒绝
3. 外卖会话：可外卖菜 + 外卖价；堂食会话：原堂食菜单与价
4. 关总开关：有未结账外卖组桌 → 拒绝；关后新开台一律堂食，配置保留
5. 外卖会话不可加堂食打包费；堂食会话不可加外卖耗材
6. 转台/并台仅同渠道
7. 营收拆分只认开台渠道；总开关关时不显示分段 UI

## 详细测试场景

### 场景 1：默认关 — 堂食路径不变

- **前置状态**：`takeaway_ordering` 关；仓库可有外卖字段
- **操作过程**：堂食桌开台 → 点菜 → 结账加打包费
- **预期结果**：行为与上线前相同；无外卖置顶、无销售方式入口
- **数据验证**：新会话 `ordering_channel=dine_in`
- **标签**：【已实现】【未验证】（本轮 UAT 在开关已开的店上测外卖路径；默认关回归留给关开关后）

### 场景 2：开开关 → 标外卖组 → 标可外卖菜

- **前置状态**：店主有 `settings.features.manage`
- **操作过程**：打开店内外卖 → 分组标外卖组「外卖UAT」挂 A-20 → 菜品 Chá Jasmin 标可外卖价 €9.90；Café 标外卖耗材
- **预期结果**：配置写入成功
- **标签**：【已实现】【已验证】（API/SQL 配置 + 后续开台加单用到）

### 场景 3：外卖桌开台与菜单

- **预期结果**：`ordering_channel=takeaway`；行单价 = 外卖价 9.9；耗材 append → `menu_item_is_packaging`
- **数据验证**：table detail 订单价 9.9
- **标签**：【已实现】【已验证】

### 场景 4：堂食桌不受外卖过滤

### 场景 5：外卖结账 — 打包费隐藏 / 耗材可选
