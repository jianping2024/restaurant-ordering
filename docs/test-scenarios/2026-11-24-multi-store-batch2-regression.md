## 场景 20 明细

账号 `ms2btwo`：白云（A）收银员，`ms2b-01`（B）店长。测试时临时给 B 的店长加上员工管理和角色管理权限，让请求能通过鉴权、真正走到「按店过滤」那一步。脚本退出时撤回，已核对撤回成功。在 B 的网址下带上 A 的对象 id：

| 请求 | 响应 |
|---|---|
| 对照：改 B 自己的角色 / 桌台、列 B 员工 | 200 |
| 菜品批量上下架（A 的菜） | 200 `ok`，A 的菜未变（按店过滤后不更新任何行） |
| 菜品排序 / 删除（A 的菜） | 404 `item_not_found` |
| 员工停用 / 重置密码 / 删除（A 的员工） | 404 `not_found` |
| 角色改名（A 的角色） | 404 `not_found` |
| 角色删除（A 的角色） | **200 `ok`，A 的角色未删除** |
| 桌台改名 / 删除（A 的桌台） | 400 `invalid_tables` / 404 `tables_not_found` |

A 店菜品、店籍、角色、桌台四张表的整体快照前后一致；A 的菜仍在售，A 的员工仍启用。

**小问题（不串店，只是返回码不一致）：** 批量上下架和角色删除碰到别的店的 id 时返回 200，数据并没有改动。其他接口都返回 404。
