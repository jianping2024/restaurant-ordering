## 1. 本次修改

| 项 | 内容 |
|---|---|
| 改了什么 | 所有原生按钮、`role="button"` 控件长按不能选中文字；链接形态主钮（`ButtonLink`）同样不能选 |
| 文件 | `apps/web/src/app/globals.css`、`apps/web/src/components/ui/Button.tsx`、`apps/ops/src/app/globals.css`、`docs/design/03-component-rules.md`、`waiter-board-card-theme.test.ts`、本报告 |

## 2. 核心业务规则

1. 【本次新增】原生 `button` 与 `[role="button"]`：不可选中文字（`user-select: none` + iOS `-webkit-touch-callout: none`）。唯一写法在各自应用的 `globals.css`。
2. 【本次新增】`ButtonLink`（`<a>`）：靠 `buttonClasses` 基类禁选。原生按钮走 globals，链接形态走基类。
3. 【已实现】输入框、textarea、普通正文：仍可选中。
4. 【已实现】楼面桌卡 / KPI（`.mesa-scroll-frame` / `.mesa-stat`）原有禁选保留。
5. 【已实现】业务页不为「按钮禁选」再散写第二套规则。

## 3. 详细测试场景

### 场景 1：登录页 — 按钮不可选字，输入框仍可选

- **前置状态**：`:3003` web 已起；打开 `/auth/login`
- **操作过程**：Headless Chrome CDP 读 `button` / `input` 的 `getComputedStyle(...).userSelect`
- **预期结果**：按钮 `none`；输入框非 `none`（实测 `auto`）
- **数据验证**：无服务端写入
- **标签**：【已验证】**pass** — 登录页 button=`none`，input=`auto`；含 `select-none` 的 Button 亦为 `none`

### 场景 2：楼面看板 — 桌卡与操作钮均不可选字

- **前置状态**：`mesa-local-uat` staff jar（`qiantai1`）写入浏览器 cookie；打开 `/dashboard/waiter`
- **操作过程**：CDP 读任意 `button` 与 `.mesa-scroll-frame` 的 `userSelect`；搜索类 `input` 对照
- **预期结果**：button / frame = `none`；input = `auto`
- **标签**：【已验证】**pass** — 21 个 button、`12` 个桌卡 frame 均为 `none`；input=`auto`

### 场景 3：已下发 CSS 含唯一按钮规则

- **操作过程**：`GET /_next/static/css/app/layout.css`，核对 `button, [role='button']` 块含 `user-select: none` 与 `-webkit-touch-callout: none`
- **标签**：【已验证】**pass**

### 场景 4：链接形态主钮（`ButtonLink`）

- **操作过程**：源码 `buttonClasses` 基类含 `select-none`；登录页带 `select-none` 的 button 计算样式为 `none`
- **标签**：【已验证】源码 + 运行时 class 路径 **pass**；独立 `<a class=ButtonLink>` 真机点按【未验证】（同基类）

### 场景 5：真机 iOS 长按 callout

- **标签**：【未验证】本环境无真机；依赖 `-webkit-touch-callout: none` 已写入已下发 CSS

### 场景 6：并发 / 顺序 / 跨端

- **不适用原因**：纯展示 CSS，无服务端状态机、无多人写冲突。
