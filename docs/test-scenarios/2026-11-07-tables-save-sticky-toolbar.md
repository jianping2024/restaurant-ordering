## 核心业务规则

1. 桌位页主操作条只有一种 sticky 表示：`dashboardStickyToolbarShellClass`（与菜单 / 备注预设相同）。
2. 保存仍只在有未保存更改时可用；行为与改前一致，仅布局钉住。
3. 不新增第二套底栏 / 平行 sticky token。

## 详细测试场景

### 场景 1：滚列表时保存仍可见

- **前置状态**：店员已登录，进入 `/dashboard/tables`，桌位列表超过一屏。
- **操作过程**：向下滚桌位列表。
- **预期结果**：员工顶栏下方仍能看到「保存桌位设置」及筛选工具行。
- **数据验证**：不触发保存则桌位数据不变。
- **异常恢复**：刷新后 sticky 仍成立。

### 场景 2：改桌号后保存

- **前置状态**：同上，挑一张空闲桌。
- **操作过程**：改桌号 → 出现「有未保存的更改」→ 点保存。
- **预期结果**：保存成功提示；dirty 清除；滚列表时仍能点到保存（在 dirty 期间）。
- **数据验证**：列表桌号与保存值一致；可再改回原号并保存（UAT 清理）。

### 场景 3：批量模式工具不滚走

- **前置状态**：进入批量管理。
- **操作过程**：勾选若干桌，向下滚列表。
- **预期结果**：批量条与保存仍在 sticky 区内。
- **数据验证**：不点批量删除则无删桌。

### 场景 4：回归 · 员工登录二维码区

- **前置状态**：滚过桌位列表卡片。
- **操作过程**：看页下方员工登录二维码区块仍在。
- **预期结果**：区块仍渲染，不被 sticky 遮挡到无法到达（可滚到底）。

- **场景 4** 【已验证】pass — 员工登录二维码区 h2 仍在。
