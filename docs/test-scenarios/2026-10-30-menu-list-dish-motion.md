# 本次改动业务场景测试报告：点餐列表动图（计费 + 开关 + 播放）

## 1. 本次修改

- **内容：** 新增 Pro 加购 `menu_dish_list_video`；须先有「菜品动图」授权；店内父子开关；客人列表缩略图复用 rail 小动图；报价计入该项。
- **角色 / 页面：** Ops 定价与功能包；店主功能设置；客人点餐列表。

## 2. 核心业务规则

1. 列表动图单独价目 + 单独授权；默认价 0；老店不自动授。【本次新增】
2. 无父授权 → 不可勾子；保存时 `sanitizePremiumKeyGrants` 清孤儿子授权。【本次新增】
3. 店开关：父关 → 子关；客人列表播 = `guestListVisible`。【本次新增】
4. 列表复用 `rail_video_url`，不另生成文件。【本次新增】

## 3. 详细测试场景

### 场景 1：价目含列表项

- **操作：** GET Ops settings/pro
- **预期：** products 含 `menu_dish_list_video`
- **标签：** 【已验证】

### 场景 2：无父不可授子

- **操作：** PUT grants 仅 `menu_dish_list_video`
- **预期：** 落库空 / sanitize 后无列表键
- **标签：** 【已验证】

### 场景 3：父+子授权与报价

- **操作：** 勾菜品动图 + 列表动图
- **预期：** 两项均在 grants；报价含两项
- **标签：** 【已验证】

### 场景 4：店开关父子

- **操作：** 有授权时开父/开子；关父
- **预期：** 关父后子关闭；无授权开子 → 403
- **标签：** 【已验证】/部分 UI 【未验证】

### 场景 5：客人列表播控

- **前置：** 父开、子开、有 rail
- **预期：** catalog `guestListMotionEnabled=true`；列表卡可挂 DishMotionVideo
- **标签：** 【已验证】API；浏览器播放 【未验证】若无本机视频素材

### 场景 6：老店不自动授列表

- **预期：** 仅有菜品动图授权的店无列表行
- **标签：** 【已验证】

## 4. 实际测试结果
