# 本次改动业务场景测试报告 · 菜品多档口出品绑定

**范围：** 菜品 `print_station_ids`（空=继承分类）；编辑菜品用「已选标签 + 搜索添加」；下单按有效档口列表各打一张出品联；厨显按列表包含匹配。

## 1. 本次修改

- DB：`menu_items.print_station_ids uuid[]`，迁移回填后删除单列 `print_station_id`
- 唯一解析：`resolveEffectivePrintStationIds`

- 入队 / 备餐 / 厨显 enrich / board 匹配 / 补单 remake 收口

## 2. 核心业务规则（不变量）

1. 菜品未选档口 → 有效列表 = 分类向上继承的单个默认（或空）
2. 菜品选了 ≥1 个档口 → 覆盖分类；下单对每个有效档口各一张 `station_ticket`（开后厨的档口仍不自动打，走上屏备餐）
3. 厨显：行出现在「有效列表包含该档口」的所有开后厨档口；行状态仍共用
4. 分类默认仍为单个 `print_station_id`（本次不改）

## 3. 详细测试场景

### 场景 1：继承分类（不选）

- **前置：** 分类已绑档口 A；菜品 `print_station_ids = []`
- **操作：** 顾客/员工加该菜
- **预期：** 只向 A 入队（或 A 开后厨则上 A 屏）
- **标签：** 【本次新增】逻辑与旧单列继承等价

### 场景 2：只绑 1 个档口（覆盖）

- **前置：** 分类绑 A；菜品显式绑 B
- **操作：** 加菜
- **预期：** 只打/上 B，不打 A
- **标签：** 【本次新增】

### 场景 3：绑 2 个未开后厨档口

- **前置：** 菜品绑 B、C；均未开后厨
- **操作：** 加菜
- **预期：** 产生 2 张 `station_ticket`（B、C 各一），同行同数量
- **标签：** 【本次新增】

### 场景 4：绑 2 个均开后厨

- **前置：** B、C 均 `kitchen_enabled`
- **操作：** 加菜 → 两档口大屏
- **预期：** 两屏都能看到该行；不自动打联；任一备餐出对应档口联；状态共用
- **标签：** 【本次新增】

### 场景 5：编辑 UI 轻量多选

- **前置：** 店内有多个档口
- **操作：** Dashboard 编辑菜品 → 点「+ 选择档口」搜索添加 → 再加第二个 → 保存 → 清空回到继承
- **预期：** 不铺开全部档口芯片；已选为可删标签；保存后列表展示多名
- **标签：** 【本次新增】

### 场景 6：回归单档口旧路径

- **前置：** 迁移后原单绑菜已回填为单元素数组
- **操作：** 加菜
- **预期：** 行为与改前一致（一张联 / 一屏）
- **标签：** 【已实现】兼容

### 场景 7：删档口

- **前置：** 菜品数组含将被删的档口 id
- **操作：** 删除该档口
- **预期：** 触发器从菜品数组中去掉该 id；分类 FK 仍 SET NULL
- **标签：** 【本次新增】
