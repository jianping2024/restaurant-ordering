# 口味分组：未挂菜可删（含组内口味）

日期：2026-11-26  
范围：删 `menu_choice_groups` 门槛改为「菜品是否引用」；未引用时一并清组内口味。

## 本次修改

- 服务端 `deleteMenuChoiceGroup`：有菜 `choice_bindings` 挂该 `group_id` → `choice_group_in_use`；否则先删 options 再删 group
- 后台提示与确认文案同步
- 产品文档 / sole 索引一句
- 分支：`fix/choice-group-delete-when-unbound`（worktree）

## 核心业务规则

1. 没有菜挂该分组 → 可删；组内口味一并删除  
2. 有菜挂着 → 不可删，须先到菜品取消勾选  
3. 口味项是否停用不影响删组判断（只看菜引用）

## 详细测试场景

### 场景 1：未挂菜、组内有口味 → 可删

- **前置**：店员登录；新建口味分组「测删组A」，加两项口味  
- **操作**：不挂任何菜；点删除分组并确认  
- **预期**：删除成功；字典里组和项都消失  
- **数据验证**：`menu_choice_groups` / `menu_choice_options` 无该组残留  

### 场景 2：有菜挂着 → 拒绝

- **前置**：分组「测删组B」+ 至少一项；某菜 `choice_bindings` 勾选该组并保存  
- **操作**：删分组  
- **预期**：失败；提示先到菜品取消勾选；带在用菜数  
- **数据验证**：组与项仍在  

### 场景 3：取消挂菜后再删 → 成功

- **前置**：场景 2 的组仍在  
- **操作**：菜品取消勾选该组并保存 → 再删组  
- **预期**：删除成功  

### 场景 4：回归 — 空组仍可删

- **前置**：新建空分组（无口味）且未挂菜  
- **操作**：删除  
- **预期**：成功
