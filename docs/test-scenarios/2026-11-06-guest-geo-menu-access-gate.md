# 本次改动业务场景测试报告：顾客点餐页 GPS 进页拦截

日期：2026-11-06  
分支：`fix/guest-geo-menu-access-gate`

## 1. 本次修改

- **内容：** 围栏开启时，顾客点餐页进页校验定位；失败则整页不展示菜单。超距主文案「请到店后再点餐」。无「重新检测」（刷新再查）。提交/寿司送厨复用同一文案；服务端围栏保留。
- **文件：** `CustomerFullscreenNotice`、`CustomerGeoMenuAccessGate`、`MenuPage`、经典/寿司提交路径、`customer-geo-order`（删 warm）、`menu-page-messages`、产品文档。
- **角色 / 页面：** 顾客扫码点餐；员工代点与 demo 不拦。

## 2. 核心业务规则

1. 【本次新增】围栏开 → 顾客进点餐页须定位通过，否则不渲染菜单。
2. 【本次新增】超距唯一主句：「请到店后再点餐」；权限/不支持/失败各有正常提示。
3. 【本次新增】无重试按钮；刷新重新检测。
4. 【已实现】服务端 append / 寿司 submit-request 仍核距离。
5. 【已实现】员工代点、demo、本机 localhost bypass 不拦顾客进页（localhost 调试约定）。

## 3. 详细测试场景

### 场景 1：超距 — 不展示菜单

- **前置状态：** 店开启 GPS 限制；浏览器定位在围栏外（非 localhost 主机名）。
- **操作过程：** 打开 `/{slug}/menu?table_id=…`
- **预期结果：** 无分类/加购；主文案「请到店后再点餐」。
- **数据验证：** 无下单写库。
- **异常恢复：** 刷新仍超距 → 同屏。

### 场景 2：范围内 — 可浏览下单

- **前置状态：** 定位在围栏内（或 localhost bypass）。
- **操作过程：** 打开点餐页，浏览菜单。
- **预期结果：** 正常菜单；可走既有下单（有桌会话时）。
- **数据验证：** 与改前一致。
- **异常恢复：** 不适用。

### 场景 3：拒绝定位权限

- **前置状态：** 围栏开；浏览器拒绝 geolocation。
- **操作过程：** 打开点餐页（非 localhost）。
- **预期结果：** 系统可先弹出权限申请；拒绝后整页提示需允许定位；无菜单。
- **数据验证：** 无写库。
- **异常恢复：** 设置里打开定位后刷新 → 再走距离判断。

### 场景 4：员工代点不拦

- **前置状态：** 服务员从看板继续点餐（staffAssisted）。
- **操作过程：** 打开员工嵌入点餐页。
- **预期结果：** 不出现地理拦截屏，可浏览。
- **数据验证：** 代点路径仍跳过顾客围栏。
- **异常恢复：** 不适用。

### 场景 5：回归 — 文案与提交同源

- **前置状态：** 已通过进页门禁后，提交时服务端/客户端再报超距（若可制造）。
- **操作过程：** 触发 geo / location_too_far 失败提示。
- **预期结果：** toast/错误与进页同一句「请到店后再点餐」。
- **数据验证：** 未写入成功单。
- **异常恢复：** 不适用。
