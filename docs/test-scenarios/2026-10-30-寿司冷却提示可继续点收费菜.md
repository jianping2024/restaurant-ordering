# 本次改动业务场景测试报告 — 寿司冷却提示：收费菜可继续点

## 1. 本次修改

- **内容：** 送厨冷却绿条 / intro 第 3 步 / 点免费菜被拦 toast，写清「收费菜可继续点；免费菜等下一轮」。状态机与门禁不变。
- **文件：** `apps/web/src/lib/i18n/sushi-round-messages.ts`（+ 单测）、`docs/product/sushi-round-ordering.zh.md`
- **角色 / 页面：** 顾客寿司扫码菜单底栏引导条；首次 intro；冷却期点免费菜 toast

## 2. 核心业务规则

1. 【已实现】冷却期服务端拒绝写免费轮次行（`round_cooldown_active`）；前端免费 `+` 弹 toast。
2. 【已实现】冷却期收费菜仍可加购并「去下单」。
3. 【本次新增】`guidanceSent` / `introStep3Body` / `cooldownActive` 同一口径：收费可继续、免费等下一轮。

## 3. 详细测试场景

### 场景 1：冷却绿条文案

- **前置状态：** 寿司桌已送厨，round=`cooldown`，倒计时未结束
- **操作过程：** 客人打开菜单，看底栏绿条
- **预期结果：** 含「收费菜可继续点」与「N 秒后开下一轮」；不含「N 秒后可点下一轮」旧句
- **数据验证：** 仅文案；round 仍 cooldown
- **异常恢复：** 不适用

### 场景 2：冷却期点收费菜

- **前置状态：** 同场景 1；购物车空
- **操作过程：** 加一道收费饮料 →「去下单」
- **预期结果：** 下单成功；绿条仍在
- **数据验证：** 订单出现该收费行
- **异常恢复：** 刷新后绿条仍在直至冷却结束

### 场景 3：冷却期点免费菜

- **前置状态：** 同场景 1
- **操作过程：** 点免费菜 `+`
- **预期结果：** toast「免费菜等下一轮；收费菜可继续点」；购物车不加该免费菜
- **数据验证：** 无新 round line
- **异常恢复：** 冷却结束后可正常加入本轮

### 场景 4：回归 — 送厨前倒计时文案

- **前置状态：** `pending_confirm`
- **操作过程：** 看绿条
- **预期结果：** 仍为「N 秒后自动送厨 · 同桌还能加」（未改）
- **数据验证：** 无
- **异常恢复：** 不适用
