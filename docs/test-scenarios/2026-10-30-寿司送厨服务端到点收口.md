## 2. 核心业务规则

1. 【本次新增】截止时间仍写在 `submit_deadline_at`；到点收口**唯一**为 `settleDueTableOrderRoundSubmit`（空篮 → `collecting`；有菜 → `finalizeRound`）。
2. 【本次新增】发起成功后服务器进程内定时；人不在页面也能送厨（店机长驻 Node）。
3. 【本次新增】**不**新增 Vercel Cron；sweep 由 API Node 进程懒启动。
4. 【已实现】finalize 幂等；与手机同时到点不重复送厨。
5. 【已实现】出品联仍由服务端入队，不依赖某台手机前台。

## 3. 详细测试场景

### 场景 1：一人确认后不调手机 finalize，到点仍送厨（主场景）

- **前置状态**：桌 92 开台 1 人；本轮写入免费菜「冰块加柠檬」×1；`status=collecting`
- **操作过程**：`POST …/submit-request` → **故意不**调 `POST …/finalize` → 等待约 18s（倒计时 15s）→ 再 `GET` round
- **预期结果**：发起后为 `pending_confirm`；等待后为 `cooldown`；订单里出现冰块加柠檬
- **数据验证**：round `cooldown`；session 订单 names 含「冰块加柠檬」
- **异常恢复**：不适用
- **标签**：【已验证】**pass**
