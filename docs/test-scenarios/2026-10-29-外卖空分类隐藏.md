# 本次改动业务场景测试报告：外卖空分类隐藏

日期：2026-10-29  
分支：`fix/hide-empty-catalog-categories-after-filter`

## 1. 本次修改

- **内容：** 客人点餐分类条只显示「渠道 + 时段筛完后仍有菜」的分类；没有可外卖菜的类、时段筛光的类、本来就空的类都不出现。
- **文件：** `apps/web/src/lib/menu-recommended.ts`（唯一规则）、同文件单测、`AGENTS.md` / `docs/agent-sole-index.zh.md` 口径一句。
- **角色 / 页面：** 客人扫码点餐、员工代点（同一目录视图）；堂食与外卖渠道共用该规则。
- **流程：** 打开点餐页 → 分类导航由 `resolveCustomerMenuCatalogView` 产出 → 无第二套 UI 隐藏。

## 2. 核心业务规则（不变量）

1. 【本次新增】分类出现 ⇔ 筛完后的可见菜集合里该分类（含子类范围）至少有一道菜。
2. 【已实现】外卖渠道只保留「可外卖」菜；耗材不进任何点餐菜单。
3. 【已实现】时段筛掉的菜不进入可见集合；推荐栏用同一可见集合。
4. 【已实现】堂食渠道仍显示有堂食可见菜的分类；空壳分类也不再显示。
5. 不得另写「仅外卖页再藏分类」的平行逻辑。

## 3. 详细测试场景

### 场景 1：外卖桌 — 仅堂食菜所在分类不出现

- **前置状态：** 店内外卖已开；存在外卖桌与会话渠道外卖；至少有一个分类下只有「仅堂食」菜，另有分类含「可外卖」菜。
- **操作过程：** 客人扫该外卖桌二维码（或员工代点进入该桌点餐页）。
- **预期结果：** 分类条不含「仅堂食」那个空类；含可外卖菜的类仍在；列表价为外卖价。
- **数据验证：** 导航分类 id ⊆ 有 `takeaway_role=sellable` 且过时段的菜的分类。
- **异常恢复：** 刷新页面后分类集合不变（仍无空类）。

### 场景 2：堂食桌 — 有堂食菜的分类仍在；空壳类不出现

- **前置状态：** 普通堂食桌开台；菜单里有空分类（无菜）以及有菜分类。
- **操作过程：** 打开该桌点餐页。
- **预期结果：** 有菜的分类显示；无菜空壳分类不显示；菜仍是堂食价。
- **数据验证：** 与场景 1 共用同一函数，渠道为堂食。
- **异常恢复：** 不适用。

### 场景 3：时段筛光 — 分类隐藏（回归）

- **前置状态：** 某分类下菜全部绑定午餐时段；当前会话时段为晚餐（或测试注入 dinner）。
- **操作过程：** 打开点餐页。
- **预期结果：** 该分类不出现；推荐里对应菜也不出现。
- **数据验证：** 单测 `menu-recommended.test.ts` 时段用例。
- **异常恢复：** 不适用。

### 场景 4：操作顺序 — 先开外卖桌再改菜为仅堂食

- **前置状态：** 外卖会话已开；某分类原有可外卖菜。
- **操作过程：** 店主把该分类最后一道可外卖菜改成仅堂食；客人刷新点餐页。
- **预期结果：** 该分类从分类条消失；若购物车仍有该菜，下单仍按既有「不可外卖」拒绝规则（本改动不改加单接口）。
- **数据验证：** 刷新后 catalog view 无该分类。
- **异常恢复：** 把菜改回可外卖并刷新 → 分类重新出现。

### 场景 5：回归 — 有可外卖菜的分类与推荐栏

- **前置状态：** 推荐里含可外卖 + 仅堂食菜；外卖渠道。
- **操作过程：** 打开外卖点餐页。
- **预期结果：** 推荐只留可外卖；分类条无空类。
- **数据验证：** 单测 takeaway 用例。
- **异常恢复：** 不适用。
