# 档口后厨大屏与当日补单（产品方案）

> **状态**：已锁定（2026-08-07）  
> **读者**：产品、开发、AI 代理  
> **原则**：一概念一写法；自动已出餐只展示计算、不写库；顾客端不上订单 Realtime。

---

## 1. 一句话

开了后厨的档口：菜上可编排的大屏、多端只读进度；厨师只做 **备餐**（出票）；到点 **展示为已出餐**；楼面可 **上桌→done**；另有当日检索与 **厨房补单**（不进顾客已下单列表）。没开后厨的档口与菜：行为保持现状。

---

## 2. 档口

每个 `print_stations`：

| 配置 | 说明 |
|------|------|
| **开启后厨流程** | 无店级总开关。开：上大屏、多端进度、下单不自动打出品联、备餐出票。关：下单自动打、不上大屏、多端不跟厨房进度（UI 保持现状，无额外文案）。 |

- 不设单独的「档口自动打印」开关（与后厨开关联动）。
- 营业中不改档口绑定；历史单归历史，新单按新绑定。
- 账单/预结自动打印（`bill_receipt_print`）保留，与档口无关。

---

## 3. 菜品状态（唯一写法）

`orders.items[].item_status`：

| 值 | 产品名 | 谁推进 |
|----|--------|--------|
| `pending` | 已下单 | 下单 |
| `cooking` | 备餐中 | 厨师 **备餐**（唯一厨师操作） |
| `ready` | 已出餐 | **有效/展示态**（见 §4）；枚举保留。首期自动路径 **不往库写 `ready`** |
| `done` | 已上桌 | 楼面 **上桌**（功能开关打开时）：库内 `cooking` → `done` |
| `voided` | 已退菜 | 仅有减餐权限者；**后厨不可退菜** |

订单级 `orders.status` 仍由行状态推导；`cooking`（含展示已到期）与库内若已有 `ready` 均视为未完结厨房作业，与 `deriveOrderStatusFromItems` **一次改齐**，禁止并行两套映射表。

旧数据无 `ready`：不影响。`done` 语义从「已出餐」改为「已上桌」（产品文案与多端展示一次替换，禁止旧「出餐=done」文案残留）。

---

## 4. 自动已出餐（展示计算，不写库）

店级配置：`kitchen_ready_after_minutes`（默认 15，可改）。

### 展示（唯一自动路径）

- 备餐时写入 `started_at`。
- **展示时计算**：若 `item_status === cooking` 且 `now >= started_at + N` → **显示为已出餐（有效态 ready）**。
- 大屏可用本地时钟重算展示，**不因此打 API**。

### 什么时候真的更新库状态？

| 时刻 | 写库？ |
|------|--------|
| 时钟刚到 N 分钟 | **否** |
| 大屏 / 楼面拉 board（进页、Realtime 对账） | **否（只读）** |
| 再备餐（补打） | **否改状态**（只入队打印；不重置 `started_at`） |
| **上桌** | **是**——唯一自动链路上的状态写：`cooking` → `done` |

**禁止**：到点回调、cron 扫行、board GET 懒晋升写 `ready`、前端 `setInterval` 调状态 API。

首期 **不为「到点」往库写 `ready`**，避免多接口写节点与 board 刷新写放大。`ready` 枚举留给读模型有效态 / 日后若要手动标已出餐；自动已出餐 = 纯展示。

### 4.1 多端会不会不一致？

| 情况 | 会怎样 | 是否可接受 |
|------|--------|------------|
| 各端用同一 `effectiveItemStatus(item, now, N)` | 到期后都显示已出餐，库仍为 `cooking` | 是（权威在公式，不在提前写库） |
| 顾客无 Realtime、一直挂页 | 可能仍显示备餐中，直到进页再拉 | **产品已接受** |
| 各端各自算 N / 时区 | 真不一致 | **禁止**——单一 helper |

**权威规则（唯一写法）：**

1. **展示/有效态** = `effectiveItemStatus(...)`（库已是 `ready`/`done`/`voided` 用库；`cooking` 到期则视为 `ready`）。
2. **自动已出餐不写库**；**上桌** 写 `cooking → done`（展示已是已出餐即可点）。
3. 大屏/楼面 Realtime = 有变更再拉（只读）；顾客只靠进页拉取。

### 补打与计时

- 已 `cooking` 再备餐 = **补打出品联**。
- **不重置** `started_at`。

---

## 5. 厨师与打印

- 厨师只有「备餐」，可多选；无「出餐」。
- 备餐：勾选行 `pending → cooking`，并出票。
- **出票：只打勾选的菜；没勾的不打。一桌一张纸。**
- 开了后厨：下单不自动打；关了后厨：维持现网下单就打。
- 已备餐可再点备餐 = 补打（仍只打勾选的；不改状态、不重置计时）。

---

## 6. 上桌

- 店级功能开关：开 → 楼面在 **有效态已出餐**（`cooking` 已到期，或库内已是 `ready`）行显示「上桌」；关 → 不显示。
- 上桌写库 **唯一路径**：`cooking` → `done`（不强制先写 `ready`）。

---

## 7. 后厨大屏

- **新实体**：大屏配置（名、有序档口列表），存店内；电视收藏稳定 URL。
- 仅可加入 **已开后厨** 的档口；最多 **4**；自动分格；单档口最大化/复原。
- Realtime **单通道** → debounce → **一次** board GET → 前端分格；未备餐的已下单一直留在屏上，直至备餐或会话不再活跃。
- **关台后不关心餐品状态**（会话关闭后自然离开看板）。

### 7.1 档口格子内两种视图（可切换）

同一份 board 数据，前端两种呈现，**禁止各拉各的接口**。

| 视图 | 用途 | 内容 |
|------|------|------|
| **按桌（正常）** | 传菜/对桌作业 | 按桌归类、时间先后；每行：菜名、本行数量、状态等。**每行菜名前面展示该菜在本档口当前板上的已点总份数**（同 `menu_item_id`、未完结行合计），让厨师一眼知道这道菜总共要做多少。 |
| **按菜** | 桌多列表太长时总览 | 按菜聚合：菜名、**总份数**、对应的 **全部桌号**（可带每桌份数）；更干净，方便先扫「要做什么、各多少」。 |

- 默认进哪个视图：首期默认 **按桌**；统计视图一键切换即可。
- 备餐多选：两种视图都要能选到具体行（统计视图点某菜可展开到各桌行再勾，或勾菜=勾其下全部未备餐行——实现取一种，文档与 UI 一致，禁止两套选择语义）。
- 「本档口已点总份数」口径：当前大屏该档口格子内、有效态未上桌（`pending` / `cooking`，含展示已出餐未上桌）的同行菜合计；`voided` / `done` 不计。

权限（能力键实现时一次注册，默认模板如下）：

| 能力 | 默认 |
|------|------|
| 配置大屏 | 店主、前台 |
| 看大屏 | 厨师（复用/演进 `floor.kitchen_board.view`） |
| 备餐 | `orders.kitchen_update` |
| 上桌 | 新权限；服务员（+前台按需） |
| 减餐 | 现有 `orders.menu_decrement`；厨师预设无 |

旧「全店一张厨房板」产品入口由大屏列表/默认大屏覆盖；代码改造成格子，禁止长期两套后厨主 UI。

侧栏 `kitchen_board` 快捷入口：改为进大屏列表或下线旧语义（实现时二选一，文档与设置文案同步）。

## 8. 多端进度

| 端 | 行为 |
|----|------|
| 大屏 / 楼面 | Realtime + 进页对账；只读或操作见上 |
| 顾客 | **不需要 Realtime**；进已下单/相关页再拉。仅 **开了后厨的档口菜** 展示进度；未开后厨的菜 UI 保持现状 |

## 9. 当日菜品检索 + 厨房补单

### 检索页

- 角色：前台、服务员（新页权限）。
- 范围：**当天本店全部点菜**，与是否关台无关。
- 按菜名 / 编号检索；列表时间序；桌号、数量等。
- 分页：可选 **20 / 50 / 100**（上限 100）。

### 补单（重做语义，非普通加菜）

**要解决的问题**：菜上错桌 / 一直没上，需要再给厨房做一份，**不要在顾客菜单「已下单」里重复冒出一行**。

| | 普通加菜 `orders.append` | 厨房补单（本方案） |
|--|---------------------------|-------------------|
| 顾客已下单列表 | 可见 | **不可见** |
| 后厨大屏 / 出品联 | 按档口规则 | 要进厨、要出票（开了后厨则走备餐票规则；实现与后厨开关一致） |
| 计费 | 正常计价 | **不计费**（客已下过单；补单因传菜/上错桌等服务失误重做，不收第二次钱） |
| 楼面账单 | 可见 | **不出现在应付/分单金额中**（与不计费一致；可仅厨房/检索侧可见，实现时一种展示） |
| 目标桌 | 当前桌会话 | **默认补到检索行那张桌**的当前活跃会话；必须 **开台**；关台不可补 |

默认带出历史行份数，可改后再确认。补单 API **单独接口/路径**，禁止与顾客可见 append 混成同一无差别入口。

## 10. 店级开关汇总（产品）

| # | 开关 | 说明 |
|---|------|------|
| 1 | 档口「后厨流程」 | 每档口 |
| 2 | `kitchen_ready_after_minutes` | 整店；自动已出餐展示阈值 |
| 3 | 「上桌」功能开关 | 整店；是否显示上桌按钮 |
| — | `bill_receipt_print` | 原有，不动 |

大屏为编排配置，不是布尔开关。

---

## 11. 已定边界 / 实现注意

1. **补单计费**：**不计费**；不进顾客已下单列表；不进楼面应付金额。默认补到 **检索行那张桌** 的当前开台会话。
2. **自动已出餐**：只展示计算，**不写 `ready`**；board/补打不晋升。
3. **上桌**：唯一写 `cooking → done`；按钮挂在有效态已出餐上。
4. **多端**：单一 `effectiveItemStatus`；顾客无 Realtime，进页再拉。

---

## 12. 首期不做

- 一行拆数量备餐  
- 后厨开着仍下单自动打（屏纸双开）  
- 大屏自由拖拽改格大小  
- 顾客订单 Realtime  
- 全店 cron / 前端 interval 改状态  
- 营业中改菜单档口绑定的迁移策略
