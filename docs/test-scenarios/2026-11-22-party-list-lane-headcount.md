- 楼面 / 同行组 tab meta：`N 桌`，有开台人数时加 ` · A… C…`（无权限或全 0 不写 A/C）
- 「同行组」改为普通 tab：点开直接出列表（创建在列表顶）；去掉下拉

- 同行组 tab 始终显示所有同行组合计（进详情也不改成组名）

## 核心业务规则

1. 人数与「用餐中」KPI 同源：只加开台用餐中桌的自助餐成人/儿童
2. 进同行组的桌不进楼面分组人数
3. 列表打开 / 组详情时不显示待结账置顶区
4. 「创建」仅筛选=全部且无搜桌时可用

## 详细测试场景

### 场景 1：楼面组按钮人数

- **前置**：至少一桌开台有 A/C；员工有看用餐人数权限
- **操作**：打开楼面看板，看大厅 tab
- **预期**：有人时 `N 桌 · A… C…`；无人只 `N 桌`
- **数据验证**：人数与组内开台桌卡 A/C 之和一致

### 场景 2：点同行组直接出列表

- **前置**：已有 ≥1 个同行组
- **操作**：点「同行组」tab
- **预期**：无下拉；主区直接列表；每行 `N 桌 · A… C…`；有「创建」
- **异常恢复**：再点大厅 tab 回桌卡

### 场景 3：进详情再回列表

- **操作**：列表点一行 → 见组详情与桌卡 → 点 `‹ 同行组`
- **预期**：回到列表，不跳大厅；顶栏「同行组」仍是合计

### 场景 4：创建

- **操作**：列表点「创建」
- **预期**：进入新组详情并可改名（沿用原逻辑）

### 场景 5：筛选非全部

- **操作**：筛「用餐中」或搜桌
- **预期**：列表无「创建」或创建不可用（沿用原门禁）
