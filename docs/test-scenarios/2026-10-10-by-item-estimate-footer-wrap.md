## 1. 本次修改

- **内容**：员工按菜分单「当前份额」底部的「本票预估 · N 行 + 金额」与按钮（恢复点单 / 收款）原先同行、按钮固定宽、文字被挤成竖排或被按钮盖住；改为可换行：放得下同行，放不下按钮掉到下一行靠右。

## 2. 核心业务规则

1. 【本次新增】文字组不得窄于自身最小内容宽度（`min-w-min`），按钮组可换行且右对齐。
2. 【本次新增】桌面单按钮（最常见）布局不变。

## 3. 详细测试场景

### 场景 1：手机 375px，未收款人带「恢复点单」+「收款」
- **前置**：VIP999 小李未收且有恢复点单。 **操作**：手机打开。 **预期**：估算文字一行；两个按钮在下一行靠右。
### 场景 2：桌面 1024px，同样两个按钮
- **预期**：同场景 1，不再竖排。
### 场景 3：桌面 1024px，仅「收款」
- **前置**：新开桌，按菜分 1A + 1 份。 **预期**：文字在左、收款在右同一行，与旧代码坐标一致。
### 场景 4：手机 320px 最窄
- **预期**：按钮各占一行右对齐，页面无横向溢出。

## 4. 实际测试结果

- 【已验证】场景 1：旧 = 文字 30×80px 竖排、行高 114；新 = 文字 96×20px 一行、行高 92。
- 【已验证】场景 2：旧 = 24×120px、行高 154；新 = 行高 92。
- 【已验证】场景 3：新旧逐项坐标相同（行高 56）。
