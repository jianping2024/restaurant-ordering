# 本次改动业务场景测试报告：设置页「使用当前位置」按钮

日期：2026-11-06  
分支：`fix/settings-geo-locate-button`  
改动面：`apps/web/src/components/dashboard/SettingsForm.tsx`

## 1. 本次修改

- 「使用当前位置」从金色文字链接改为 `Button`（outline / sm），定位中有 loading。
- 经纬度输入区不再随「要求顾客 GPS 下单」开关变淡；开关关着也能看清坐标、能点定位。
- 未加新文案。

角色 / 页面：店主 · 仪表盘 · 餐厅设置（`/dashboard/settings`）。

## 2. 核心业务规则

1. 店主可随时填写或用浏览器定位写入经纬度（与开关无关）。
2. 仅当「要求顾客 GPS 下单」打开且未填齐坐标时，保存会被拒（原有校验）。
3. 浏览器无定位能力或用户拒绝权限 → 显示已有失败提示 `geoLocateFail`，坐标不变。

## 3. 详细测试场景

### 场景 1：开关关闭时按钮仍清晰可点

- **前置**：店主登录；进入设置；「要求顾客 GPS 下单」未勾选；经纬度可为空。
- **操作**：看经纬度输入与「使用当前位置」按钮；点击按钮。
- **预期**：输入与按钮无淡化；点击后进入定位流程（loading 或权限弹窗 / 失败提示）。
- **数据验证**：未获权限时坐标仍为空；获权限时写入 6 位小数。
- **标签**：【本次新增】【已验证】UI：按钮可见、`opacity` 未淡化、点击后出现失败提示（自动化环境无定位权限）。

### 场景 2：开关打开 + 有权限填坐标（人工）

- **前置**：浏览器允许站点定位；开关可开可关。
- **操作**：点「使用当前位置」；看 lat/lng 填入；可选保存。
- **预期**：坐标写入；保存后服务端有对应值。
- **标签**：【已实现】【未验证】Chrome DevTools 自动化无定位权限，本环境只能验失败路径。

### 场景 3：拒绝定位权限

- **前置**：拒绝或无法提供定位。
- **操作**：点按钮。
- **预期**：提示定位失败；坐标不变；按钮恢复可点。
- **标签**：【已验证】出现 `geoLocateFail` 文案；lat/lng 仍空；按钮重新可点。

### 场景 4：回归 — 开关与保存校验

- **前置**：开关打开、坐标空。
- **操作**：点保存。
- **预期**：仍要求坐标（原校验）。
- **标签**：【已实现】【未验证】本次未改保存逻辑；代码路径未动。

### 不适用

- 多用户并发、Realtime、结账/打印：与本 UI 无关。
