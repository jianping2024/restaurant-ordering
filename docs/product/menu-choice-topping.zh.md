# 口味分组 + 关联菜品（点单配置）

店员给主菜挂「点单时必须/可选的配置」；与 **风味提示**（只展示）和 **预选备注**（选填文案）分开。

人对人叫 **关联菜品**；库列 / 代码仍用 `topping_binding`（不迁库、不双写）。

## 口味分组

- 全店共用字典：`menu_choice_groups` + `menu_choice_options`（三语文案）
- 菜品 `choice_bindings`：`[{ group_id, option_ids[] }]`
- **后台挂菜：只选分组**（可多组）；选上某组 = 该组全部选项；`option_ids` 空 = 该组全部。不展开、不挨个勾组内项
- 顾客：每个挂上的分组 **单选、必选一**
- 无价格；结果进主菜行备注/选项快照（跟厨可见）
- 旧数据若曾写过非空 `option_ids`，顾客端仍按子集；店员打开菜品再保存后写成整组（空 `option_ids`）

## 关联菜品

- 菜品 `topping_binding`：`{ category_id, item_ids[], required }` 或 `null`
- **挑选一个类别**；可勾「该类全部」（`item_ids` 空），或子集：`item_ids` 非空
- **后台子集展示：** 主区只显示已选菜；点「添加关联菜品」从本类剩余里挑（可搜）。子集至少留一个（空 `item_ids` 表示全部，不能当「一个都没选」）
- `required`：顾客是否必须至少选一种（可改数量）
- 关联菜品是真菜，主菜单可单独点；有价，下单时展开为独立行（或等价进单）

## 点餐交互

- 未挂口味且未挂关联菜品：列表可直接加减
- 挂了任一：列表加号进详情，必选未完成不能加入
- 购物袋分行：主菜 + 口味选择 + 关联菜品组合（含数量）+ 备注（预选+手写）全部相同才叠份
- **展示：** 购物袋行下只读口味摘要 + 已选关联菜品（名/份数/价）；顾客「已点」与店员桌台详情「已点」行下展示该行说明（口味文案 + 备注）。关联菜品下单后仍是独立行。桌台详情列表：同一菜同一说明才叠份（收钱合计仍按原计价合并，不看说明）

## 明确不做

- 不用 `flavor_codes` 充当点单选项
- 不用预选备注充当口味组/关联菜品
- 不为无价口味建假菜
- 关联菜品不一次列出全店所有类别；先选一个类别再勾菜
- 后台口味不展开组内项逐个勾（与「只选分组」终态冲突）
