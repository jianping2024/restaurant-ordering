# 本次改动业务场景测试报告：批量生成动图确认面板

## 1. 本次修改

- **内容：** 菜单管理批量生成动图改为「工具栏打开确认面板」：候选 = 当前筛选列表里有静图且无动图；面板内勾选 + 指定一种效果后生成。日常列表行不出现批量勾选。已有动图永不进入候选。
- **文件：** `DishVideoBatchModal.tsx`、`MenuManager.tsx`、`MenuItemPhotoField.tsx`、`menu-dish-video.ts`（`DISH_VIDEO_EFFECT_MESSAGE_KEYS`、`menuItemEligibleForDishVideoBatch`）、`messages.ts`、设计图 `docs/design/mockups/2026-10-30-dish-video-batch.html`、sole 索引、本场景文档。
- **角色 / 页面：** 有 `dashboard.menu.video.manage` + Pro 菜品动图的店主/员工；菜单管理 · 菜品列表。

## 2. 核心业务规则

1. 可批量候选唯一判定：有 `image_url` 且无 `video_url`（`menuItemEligibleForDishVideoBatch`）。【本次新增】【已实现】
2. 候选范围 = 打开面板瞬间的当前筛选 `visibleItems` 快照；已有动图不进面板。【本次新增】【已实现】
3. 本轮共用一种效果；效果文案键唯一 `DISH_VIDEO_EFFECT_MESSAGE_KEYS`（表单芯片与批量面板共用）。【本次新增】【已实现】
4. 日常列表行不出现批量勾选框。【本次新增】【已实现】
5. 编码与写入仍走 `encodeDishVideos` + `setMenuItemImageClient`；成功后该菜有动图，不再出现在后续批量候选。【已实现】

## 3. 详细测试场景

### 场景 1：工具栏打开面板，列表无勾选

- **前置状态：** 白云店主登录；菜单菜品 Tab；当前分类下至少 1 道有图无动图、1 道已有动图
- **操作过程：** 看列表行 → 点「批量生成动图（n）」
- **预期结果：** 列表行无批量勾选；面板列出候选；已有动图不在面板
- **数据验证：** 面板候选数 ≤ 工具栏 n；n = 当前页有图无动图数
- **异常恢复：** 取消关闭面板，列表仍无勾选
- **标签：** 【已验证】UI

### 场景 2：面板取消个别勾选后只生成剩余

- **前置状态：** 面板打开且默认全选 ≥2 道
- **操作过程：** 取消 1 道勾选 → 选效果「热气腾腾」→ 生成
- **预期结果：** 仅勾选的菜写入动图；`video_effect` 为 steam；未勾选仍无动图
- **数据验证：** 成功菜有 `video_url`/`rail_video_url`；提示含效果名
- **异常恢复：** 刷新列表后未勾选菜仍可再进候选
- **标签：** 【已验证】UI（选效果+取消勾选）；【未验证】本机完整编码写库（耗时长，见结果表）

### 场景 3：切换分类后工具栏计数只反映当前页

- **前置状态：** 分类 A 有可生成菜；分类 B 无可生成（或较少）
- **操作过程：** 切分类，看工具栏 n；再打开面板
- **预期结果：** n 与面板候选随当前筛选变；不混入其他分类缺动图菜
- **数据验证：** 对比切分类前后工具栏文案
- **异常恢复：** 无
- **标签：** 【已验证】UI

### 场景 4：无候选时不出现可点批量（或 n=0 不可开）

- **前置状态：** 当前筛选全部无图或已有动图
- **操作过程：** 看工具栏
- **预期结果：** 不出现可点的批量按钮（或无可生成时不展示）
- **标签：** 【已验证】UI（饮品等已全有动图/无图的筛选）

### 场景 5：效果文案唯一写法

- **前置状态：** 代码 diff
- **操作过程：** 搜索 `EFFECT_LABEL_KEYS` / 平行效果 map
- **预期结果：** 仅 `DISH_VIDEO_EFFECT_MESSAGE_KEYS`；表单与批量面板共用
- **标签：** 【已验证】代码

### 场景 6：单道编辑动图效果回归

- **前置状态：** 打开一道菜编辑弹窗（有图）
- **操作过程：** 看动图效果芯片
- **预期结果：** 六种效果 +「不生成」仍在；文案正常
- **标签：** 【已验证】UI

## 5. 风险与待确认

- 大批量串行编码仍占本机 CPU；面板缩小范围后风险低于「全店一键」。
- 打开面板后若他端改了菜品：以打开瞬间快照为准（实现如此）。
