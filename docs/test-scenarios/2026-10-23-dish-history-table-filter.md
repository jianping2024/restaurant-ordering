# 本次改动业务场景测试报告：当日菜品检索 · 桌号筛选

日期：2026-10-23  
分支：`feat/dish-history-table-filter`  
UAT base：`http://localhost:3002`（功能分支，非 `:3000`）

## 1. 本次修改

- **内容**：当日菜品检索增加「桌号」多选（全店桌位、可输入定位），放在菜名左侧；去掉搜索按钮；桌号与菜名均防抖实时查询。
- **文件**：`DashboardTableMultiSelect`、`loadActiveRestaurantTableRows`、`DishHistoryManager`、`dish-history` 页/API/`listDishHistory`、`parseCommaSeparatedTableIds`、历史订单改用共用控件、i18n、sole 索引、设计稿。
- **角色 / 页面**：有 `dashboard.dish_history.view` → `/dashboard/dish-history`。

## 2. 核心业务规则

1. 未选桌 = 不按桌过滤；选了 = 只出这些桌 `table_id` 的当日行（并集）。
2. `q` 与桌号可同时生效；分页按过滤后全集。
3. 选项 = 本店未删除桌位；框内输入只定位选项。
4. 无搜索按钮；条件变更自动刷新。
5. 厨房补单逻辑不变。
