# 楼面桌子组手机竖排按钮

日期：2026-11-23  
分支：`fix/waiter-board-lane-mobile-vertical`  
UAT 基址：`http://localhost:3002`（功能分支，非 `:3000`）

## 本次修改

- 手机（&lt;640px）：桌子组 +「同行组」改成竖着排的满宽按钮，方便点。
- 电脑（≥640px）：仍是横滑一排。
- 组很多时，手机上这排按钮区域限高，组条自己上下滑，不把下面桌卡全挡住。
- 文件：`waiter-board-card-theme.ts`、`WaiterDisplay.tsx`、`globals.css`（`.mesa-board-lane-tablist`）、设计/sole 文档。

## 核心业务规则

1. 点哪个组，只显示该组桌卡——规则不变。
2. 「同行组」仍在桌子组后面；点进去还是整页列表。
3. 手机竖排 / 电脑横排是同一套按钮，不是两套入口。

## 详细测试场景

### 场景 1：手机竖排点组

- **前置状态**：员工 `qiantai1` 登录白云店；店有 VIP1、VIP2、外卖UAT。
- **操作过程**：手机宽打开楼面看板；看桌子组是否竖排；点 VIP2。
- **预期结果**：组名竖着一条条；VIP2 选中；主区是 VIP2 的桌。
- **数据验证**：不改库；只改展示布局。
- **异常恢复**：刷新后仍是上次选中的组（原有偏好逻辑）。

### 场景 2：手机进同行组

- **前置状态**：同上。
- **操作过程**：点「同行组」。
- **预期结果**：主区出现同行组列表页（可创建/点进某组）。
- **数据验证**：无写库。

### 场景 3：电脑仍横排

- **前置状态**：同上。
- **操作过程**：浏览器拉到 ≥640px 宽。
- **预期结果**：桌子组恢复横着一排（可横滑）；点组仍切换桌卡。
- **数据验证**：无写库。

### 场景 4：回归 — KPI / 搜桌 / 桌卡

- **前置状态**：手机或电脑看板。
- **操作过程**：点 KPI「用餐中」、搜桌名、点一张桌卡。
- **预期结果**：筛选/搜索/进详情与改前一致；不被竖排按钮挡住无法点。
