# 本次改动业务场景测试报告 · 菜品按套餐取价（一桌一套餐）

分支 `claude/buffet-dish-price-61f9c9`，4 个提交。本地 :3003（`.next-uat`）+ 本地 Docker Supabase，店铺 白云 `restaurant-mohnrib5`（寿司模式）。证据行在 `.mesa-agent-gates/claude__buffet-dish-price-61f9c9/uat.md`。

## 1. 本次修改

1. 一桌一套餐：开台 / 详情 / 结账调人数统一成「单选套餐 + 一组人数」；接口请求体 `buffet` 单对象；改套餐接口字段白名单（修跨店越权）。
2. 菜品按套餐单独定价：新表 `menu_item_buffet_prices`；唯一取价函数；菜单、购物车（含加料）、下单、寿司轮次全部走它；后台菜品表单「Buffet 价格」。
3. 可开台时段 + 开台列表 + 缺价红色提示 + 套餐描述（≤40 字，只在开台选套餐时显示）。
4. 换套餐重算菜价、进入结账后锁定换套餐、写入时锁内核对套餐、并台套餐不同即拒、寿司轮次提交再查免费。

## 2. 核心业务规则

- 单价：外卖走外卖价（不看套餐）；堂食 = 这桌当前套餐的配置价，没配置用原价；没套餐（0 人）用原价。
- 这桌当前套餐 = 最新一条未作废的人头行（TS / SQL 各一个函数，平价测试）。
- 进入结账 = 整桌呼叫结账（billing / requested）、按人呼叫过、有收款、有开票任务；之后不能换套餐（含改成 0 人、0 人加回），人数仍可调（按已收下限）。预结单打印没有按桌记录的状态，不计入。
- 换套餐（X→Y / X→无 / 无→X）：所有有效普通菜品行按新套餐重算单价与寿司每人限量；外卖开价、打包费、人头、后厨重做行不动；菜单里已删除的菜保留原价。
- 可开台：全店当前时段（离现在最近）+ 今天日历类型下有生效规则的启用套餐；只拦冷开台与换套餐。

## 4. 实际测试结果

- 场景 1–12【已验证】（API + 浏览器 + 本地库查询，见 uat.md）。
- 寿司轮次「提交时再查免费」【已验证，但有前提】：本地库是共享的，main 的 :3002 服务也在跑轮次自动送厨（旧代码）。测试时临时去掉旧 5 参数 append 才排除干扰：本分支多次结算都失败、没有写入；恢复后 main 的旧代码马上把那轮按 €2 写入。合并部署后只有新代码，不存在这个问题。
- 并发核对【已验证】：直接调 RPC（回滚事务）验证 `buffet_changed` / `lines_changed`；真实两人同时操作的竞态【未验证】（难以人工复现，靠锁内核对保证）。
- 跨店 RLS【已验证】：其他店账号写入被拒；读取按规格公开（同 `menu_items`）。

## 5. 风险与待确认

- 结账页「调整开台人数」弹窗：桌上没有套餐时仍让选一个套餐；按「进入结账后不能换套餐（含 0 人加回）」规则，这时会被 409 拒绝 → 需要店主决定：这种情况是否允许补选套餐（会按套餐重算菜价）。
- 描述长度 CHECK 单独放在 `20261107151000_buffet_description_length.sql`：推到线上前先只读查线上是否有超过 40 字的描述。
- 本地库额外恢复了旧 5 参数 `append_order_items`（只为让 main 的本地服务不坏），合并后要删掉。
- `merge_table_sessions` / `merge_multiple_table_sessions` 的 3 参数旧重载仍在、仍可被 authenticated 调用，没有新的套餐规则（应用不调用）。
- `updateBuffetTimeSlot` 同样把 patch 原样写库（跨店越权风险），本次未改。
