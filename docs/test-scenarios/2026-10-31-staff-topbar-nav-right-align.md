# 本次改动业务场景测试报告：职员顶栏菜单靠右对齐

日期：2026-10-31  
分支：`fix/staff-topbar-nav-right-align`

## 1. 本次修改

- **内容：** 职员顶栏右侧「菜单 + 身份」整组贴右：身份（如「前台」）贴内容区右缘；菜单 chips 贴在身份左侧往左排；店名仍在左、完整显示。不再从店名右边开始往右排菜单。
- **文件：**
  - `apps/web/src/lib/waiter-staff-sticky-chrome.ts`（sole：`rightClusterClassName` 加 `justify-end`）
  - `apps/web/src/lib/waiter-staff-sticky-chrome.test.ts`
  - `docs/design/04-mobile-rules.md`
- **角色 / 页面：** 任一职员 Dashboard 顶栏（楼面看板、结账请求等共用 `StaffPersonalTopBar` / `DashboardTopBar`）
- **流程：** 纯顶栏排版；不改登录、开台、点单、结账写路径

## 2. 核心业务规则

1. 【本次新增】宽屏（`≥lg`）：店名在左；菜单 + 身份为一簇贴右；身份贴内容区右缘。
2. 【已实现】店名完整显示、不截断（`brand` `shrink-0`）。
3. 【已实现】菜单项过多时仅在簇内 `.mesa-chip-scroll` 横滑，不挤店名、不撑出整页横滑。
4. 【已实现】窄屏（`<lg`）：菜单收成 ☰；☰ + 身份仍在右簇内。
5. 【已实现】顶栏排版 sole token：`staffTopBarChrome.rightClusterClassName`（簇内靠右只有这一处）。

## 3. 详细测试场景

### 场景 1：宽屏楼面看板 — 菜单与身份贴右

- **前置状态：** 职员已登录（前台或店主）；浏览器视口 ≥1024px；打开楼面看板。
- **操作过程：** 打开 `/dashboard/waiter`（或该角色的落地看板），观察顶栏从左到右：FARVOO、店名、菜单 chips、身份文案。
- **预期结果：** 店名在左；身份贴顶栏内容区右缘；菜单 chips 紧挨身份左侧；店名与首个菜单之间可有空白（空白在中间，不在身份右侧）。
- **数据验证：** 无服务端数据变更。
- **异常恢复：** 不适用（只读排版）。

### 场景 2：宽屏切换其它顶栏页 — 对齐不变

- **前置状态：** 同场景 1。
- **操作过程：** 点击「结账请求」或「历史订单」等顶栏项进入对应页。
- **预期结果：** 顶栏仍是店名左、菜单+身份贴右；当前页 chip 高亮；身份仍贴右。
- **数据验证：** 无写库。
- **异常恢复：** 不适用。

### 场景 3：窄屏 — 汉堡与身份贴右

- **前置状态：** 视口 &lt;1024px；职员已登录。
- **操作过程：** 打开楼面看板，看顶栏。
- **预期结果：** 无横向菜单 chips；右缘为 ☰ + 身份；店名仍在左完整可见（过长时布局以既有 shrink 规则为准，本改动不改店名规则）。
- **数据验证：** 无写库。
- **异常恢复：** 点 ☰ 能打开菜单面板；关后面板消失。

### 场景 4：回归 — 店名仍完整、不截断

- **前置状态：** 宽屏；店名含空格的完整名（如本地 UAT 店名）。
- **操作过程：** 看顶栏店名文字。
- **预期结果：** 店名整串可见，无省略号截断；菜单仍贴右。
- **数据验证：** 无写库。
- **异常恢复：** 不适用。

### 场景 5：多角色 / 并发 / 历史数据

- **不适用原因：** 本次只改 CSS flex 对齐；不改权限、会话、订单、Realtime。窄屏/宽屏与换页已覆盖主要可见面。

## 5. 风险与待确认

- 极宽屏上店名与菜单之间空白变大是预期（靠右），不是缺陷。
- 「前台」与视口右缘之间仍有内容区左右 pad（与店名左边 pad 同一套 `STAFF_SHELL_CONTENT_CLASS`），贴的是内容区右缘，不是浏览器物理边。
- 菜单项极多时仍依赖簇内横滑；本轮未刻意压到溢出极限 — 【未验证】极限横滑手感。
