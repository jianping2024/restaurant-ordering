# 清理业务数据（交付前）

**状态：已落地** · 入口：餐厅设置 → 基本资料底部

## 做什么

店主（管理员账号）在交付前一键清掉本店**测试业务痕迹**，交给客人干净环境。云店与本地部署同一按钮，清的是当前环境里这家店的库。

## 谁能点

仅 `restaurants.owner_id` 对应的管理员登录（`principal.kind === 'owner'`）。有「改资料」权限的员工看不到、也调不通接口。

## 确认

1. 输入本店 slug  
2. 再弹一次危险确认  

两次都要对；slug 不对不删。

## 清什么 / 留什么

| 留下 | 清掉 |
|---|---|
| 店资料、菜单、桌台、员工与角色 | 开台会话、点单、结账、收款、寿司轮次 |
| 打印档口、后厨大屏、打印助手配对/设备 | 打印队列、钱箱任务、账单同步挂单 |
| 自助餐规则、功能开关、授权安装、财税签名安装 | 营业统计、操作记录、异常记录、菜品反馈 |
| | 临时同行组 |
| | **开票助手本机已开发票**（有配对设备时先挂队清票，成功后再清 Mesa） |

## 税控顺序

1. 若本店有未吊销的打印/开票助手设备 → 入队 `fiscal_clear_jobs`，等 Agent 清本机票库并 ack（超时/失败则**不**清 Mesa，提示重试）  
2. 再执行 `clear_restaurant_business_data` RPC 清 Mesa 运行数据  

无配对设备时跳过税控步，只清 Mesa。

## 不是什么

- 不是 Ops「删除整家店」（那条会删店与账号，且清不了店机库）  
- 不是 `supabase db reset`
