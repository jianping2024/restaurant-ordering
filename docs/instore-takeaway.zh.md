# 店内外卖（需求定稿）

> **状态：需求已定稿，待实施**
> 关联：[桌位分组](./restaurant-table-groups.zh.md) · [功能开关](./restaurant-features.zh.md) · [加单价格可信](./menu-order-append-price-trust.zh.md)

---

## 0. 一句话与边界

**店内外卖** = 店主建一个「外卖组」，组内桌台扫码或员工代点时只看到「可外卖」菜品、按外卖价下单；出单、结账、开票、关台与堂食完全相同；外卖桌结账时员工可手动加「打包类」商品（餐盒/杯等，可不加）；开台时记下「这桌是外卖」，重打小票与营收拆分都认这笔记录。

| 名称 | 含义 | 与本需求关系 |
|------|------|--------------|
| 店内外卖 | 本文档的新功能 | — |
| 现有「打包费」TAKEAWAY（`OrderItemKind 'takeaway'`，`takeaway_vat_rate`，收银员手填单价） | **堂食**没吃完打包带走的费用 | **保持不变**；外卖桌结账界面隐藏该按钮，接口也拒绝 |
| 打包类商品（新） | 外卖用的餐盒、杯子等 | 仅外卖桌结账时可加；单价 = 该商品自己的价格；**可不加，不拦结账** |

## 1. 全链路总览

```
① 总开关「店内外卖」开启
   │
   ├─② 桌位分组：用外卖图标标成「外卖组」（全店唯一）
   │      └─ 组内桌台 = 外卖桌（楼面看板中外卖组固定排最左）
   │
   ├─③ 菜品：勾「可外卖」+ 外卖价（必填 > 0）
   │
   └─④ 菜品类别：把一个类别设为「打包类」（全店唯一，无子类）
          └─ 类内商品 = 打包商品（不进任何点餐菜单）

⑤ 员工在楼面看板外卖组开单（无人数、无自助基价）
   └─ 开台时记下「外卖」身份（会话上保留）
   └─ 开台小票开关开 → 打印外卖开台小票（含扫码点餐二维码）

⑥ 点单：员工代点 或 客人扫码（普通点餐页）
   └─ 只显示可外卖菜品 · 外卖价 · 服务端同一规则校验与定价

⑦ 出单：档口小票 / 厨房屏照常，标「外卖」（认开台记下的身份；重打仍标）

⑧ 结账：与堂食相同（含分单）
   └─ 员工可手动加打包商品（选商品 + 数量）；不加也能结账

⑨ 收款 · 开票 · 关台：与堂食相同
   └─ 营收：今日卡 / 区间营业额 / 日统计 / 增值分析均可按堂食·外卖筛或对比（认开台身份）
   └─ 总开关关闭 → 上述界面不显示外卖/渠道拆分，只显示合计
```

## 2. 总开关「店内外卖」

| 项 | 规则 |
|----|------|
| 位置 | 功能开关页，唯一编辑入口 `FeatureFlagsManager`；flag 键 `takeaway_ordering`，默认关 |
| 权限 | `settings.features.manage` |
| 开启后解锁 | 分组上的外卖图标标记、菜品类别「设为打包类」、菜品表单「可外卖 / 外卖价」 |
| 关闭前检查 | 外卖组有未结账桌台（会话 `open` / `billing`）→ **不允许关闭**，提示：「外卖组还有未结账的桌台」 |
| 关闭二次确认 | 标题「关闭店内外卖？」，正文「外卖组的桌台将变回堂食桌。」，按钮〔取消〕〔确认关闭〕（危险色） |
| 关闭后 | 外卖组**变回普通分组**：桌位管理与楼面看板照常显示（组名、组员不变；外卖图标入口隐藏），看板分区不再固定最左、按原 `sort_order` 排；组内桌台按堂食处理（开台选人数/套餐、全部菜品、堂食价）；打包类商品**仍不进**点餐菜单（打包类身份不随开关改变，见 §5）；菜品可外卖 / 外卖价、外卖组标记、打包类标记**全部保留不删**，只隐藏；重新开启即恢复。已关台的外卖会话（历史）不受影响：重打仍标外卖，营收仍算外卖（有未结账外卖桌时开关关不掉，故不存在「进行中」的情况） |

## 3. 外卖组（桌位分组）

| 项 | 规则 |
|----|------|
| 设置位置 | 桌位管理 → 分组管理；总开关开启时，分组新增/编辑用**外卖图标**标记「这是外卖组」（不用长文案「设为外卖组」；点按/悬停可带一句说明）；总开关关闭时不显示该入口 |
| 唯一性 | 全店最多一个外卖组（DB 部分唯一索引保证）；已有外卖组时，其它分组的外卖标记不可用并说明原因 |
| 外卖桌 | 外卖组内的桌台；与普通桌一样有桌号、二维码；QR 卡片/打印显示分组名 |
| 楼面看板 | 总开关开启时，外卖组分区固定排在分组行**最左**，不受分组 `sort_order` 影响；入口即此分区，不另加按钮 |
| 总开关关闭时 | 变回普通分组（见 §2），标记保留，重新开启自动恢复 |
| 变更锁 | 组内任一桌台有未结账会话（`open` / `billing`）时，**不允许**：增删组员、取消外卖组标记、删除外卖组 |
| 转台 / 并台 | **仅外卖组内的桌 ↔ 外卖组内的桌**允许；外卖桌 ↔ 堂食桌**禁止**（界面不提供目标 + 接口拒绝） |
| 同行组 | 外卖桌**不能**加入同行组（界面不提供 + 接口拒绝） |

## 4. 菜品「可外卖」

| 项 | 规则 |
|----|------|
| 表单 | 价格下方：开关「可外卖」；打开后显示「外卖价」，**必填且 > 0** |
| 总开关关闭时 | 两个字段隐藏且不校验，不影响普通保存；值保留 |
| 税率 | 外卖下单的税率 = 该菜 `vat_rate`（与堂食一致） |
| 菜品列表 | 信息行（meta）显示「外卖 €x」；标题仍为 `formatMenuCatalogItemLabel` |
| 价格快照 | 已下单的行保持下单时价格；改外卖价只影响之后的新单 |
| 打包类商品 | 表单不显示「可外卖」（见 §5） |

## 5. 打包类别与打包商品

| 项 | 规则 |
|----|------|
| 设置位置 | 菜品类别编辑加开关「设为打包类」；总开关关闭时不显示 |
| 唯一性 | 全店最多一个打包类（DB 部分唯一索引） |
| 结构 | 打包类必须是**单个类别、没有子类别**；有子类别的类别不能设为打包类，打包类下不能再建子类别 |
| 设为打包类的前置条件 | 类别内有「可外卖」或「推荐」的菜品 → **不允许**设置；否则弹一句确认：「该类商品将不再出现在点餐菜单中」 |
| 菜单可见性 | 打包商品**不出现在任何点餐菜单**（客人扫码、员工代点、堂食、外卖）；点餐加单接口也拒绝打包类商品 |
| 打包商品表单 | 隐藏：可外卖、外卖价、推荐、时段、档口、口味、过敏原；**商品编码必填**（开票用）；价格用该商品自己的定价 |
| 使用场景 | 仅外卖桌结账时可选添加（§8）；**不加也能结账** |

## 6. 外卖桌开单与点单

### 6.1 开单

| 项 | 规则 |
|----|------|
| 谁开 | 员工在楼面看板外卖组分区点桌台开单；客人**不能**自行开台（与堂食一致） |
| 开单内容 | 不填人数、不选自助餐套餐、无自助基价、无人头费；直接开会话 |
| 开台记下身份 | 开台成功时在会话上记下「外卖」；之后改分组、关总开关、关台，都不改这笔记录 |
| 开台小票 | 遵循现有开关 `open_table_receipt_print`：开 → 打印外卖开台小票，内容含桌名、时间、**该桌扫码点餐二维码**；关 → 不打印 |
| 堂食开台小票 | **保持现状**（档口单格式、一行合计，无二维码） |

### 6.2 点单

| 项 | 规则 |
|----|------|
| 入口 | 员工代点（楼面桌台详情 → 点餐页 `from=waiter`）或客人扫外卖桌二维码 |
| 页面 | 一律**普通点餐页**；寿司店的外卖桌也不用 `SushiMenuPage`（无轮次界面）；轮次点餐接口对外卖桌拒绝 |
| 点单模式 | 一律单点：无自助基价、无轮次、`per_person_qty_limit` / `over_limit_unit_price` 不生效 |
| 可见菜品 | 只显示「可外卖」菜品；推荐栏同样过滤；过滤后为空的分类隐藏；菜品时段规则照常生效 |
| 显示价格 | 外卖价 |
| 服务端校验 | 加单按会话渠道（§11.2）判定菜单与定价；非可外卖菜品 → 拒绝（`menu_item_not_takeaway`）；单价取外卖价，不信任客户端价格 |
| 购物车失效 | 购物车里的菜在下单前被关掉「可外卖」→ 下单被拒，点餐页提示并移出该菜 |
| 扫码限制 | 地理围栏等现有扫码规则照常 |

## 7. 出单

| 项 | 规则 |
|----|------|
| 档口小票 | 照常按档口出单；桌名为外卖桌 `display_name`；**单头标「外卖」**（认会话开台记下的身份） |
| 厨房屏 | 照常显示；外卖桌标「外卖」（同上） |
| 重打 | 重打出品单 / 开台小票时**继续标「外卖」**，不因后来改分组或关总开关而变成堂食 |
| 打包商品 | 不进档口小票、不进厨房屏（行类型 `packaging`，见 §10.2） |

---

## 8. 结账

| 项 | 规则 |
|----|------|
| 流程 | 与堂食完全相同：整桌、AA、按菜分单（各付各）均可用 |
| 加打包商品 | 外卖桌结账界面显示「加打包商品」：从打包类选商品 + 填数量，**员工手动**添加；交互参考现有打包费弹窗；单价 = 打包商品自身价格 |
| 可不加 | **不强制**加打包商品；不加也不拦截账、收款、关台 |
| 打包商品行 | 单独成行、可改可删（复用现有打包费的写入、防重、作废链路）；名称 / 编码 / 税率 / 单价取打包商品自身；开票单独成行 |
| 原打包费按钮 | 外卖桌结账界面**隐藏**；堂食桌不变；外卖桌调用原打包费接口 → **拒绝**；堂食桌调用加打包商品接口 → **拒绝** |
| 分单中的打包商品行 | 与现有打包费行规则一致（实施时核实代码后写明） |
| 权限 | 加打包商品 = 现有加打包费同一权限 |
| 收款 / 开票 / 关台 | 与堂食相同 |

## 9. 营收按堂食 / 外卖拆分

开台记下的「外卖 / 堂食」身份是唯一口径：关台落账、收款进日统计、首页今日营业额、区间营业额、增值分析都认它；后来改分组或关总开关**不改写**已开台会话的渠道。

| 项 | 规则 |
|----|------|
| 今日营业额卡 | 总开关**开启**时：保留现有「已收 + 未收」大数字；其上增加分段 **全部 / 堂食 / 外卖**。选「全部」时大数字为合计，其下多一行小字「堂食 €x · 外卖 €y」做对比（**只拆已收**：两项之和 = 已收大数字）；选「堂食」或「外卖」时大数字只显示该渠道（外卖无人头；桌数可按渠道拆）。示意稿：[`docs/design/instore-takeaway-revenue-mock.html`](./design/instore-takeaway-revenue-mock.html) |
| 区间营业额 | 总开关**开启**时：同一套分段 + 选「全部」时的对比行 |
| 日统计 / 关台落账 | 写入时带上开台渠道，历史日数字不因后来改配置而变；上线前的历史会话与日统计一律补为「堂食」 |
| 增值分析 | 总开关**开启**时：同一「全部 / 堂食 / 外卖」分段筛指标；不另起第二套渠道控件 |
| 总开关**关闭**时的界面 | **不显示**分段与「堂食·外卖」对比行；页面只呈现与现在一样的合计。库里渠道历史仍保留；重新开启后再显示 |

## 10. 变更约束汇总

| 操作 | 条件 | 结果 |
|------|------|------|
| 关闭总开关 | 外卖组有未结账桌台（`open` / `billing`） | 拒绝 + 提示 |
| 关闭总开关 | 无未结账外卖桌 | 二次确认后关闭 |
| 外卖组增删组员 / 取消标记 / 删除 | 组内有未结账会话（`open` / `billing`） | 拒绝 |
| 设第二个外卖组 | 已有外卖组 | 拒绝（置灰） |
| 设打包类 | 有子类别 / 类内有可外卖或推荐菜 / 已有打包类 | 拒绝 |
| 外卖桌 ↔ 堂食桌 转台、并台 | 任意 | 拒绝 |
| 外卖组内桌 ↔ 外卖组内桌 转台、并台 | 两侧都是外卖组内桌 | 允许 |
| 外卖桌加入同行组 | 任意 | 拒绝 |
| 外卖桌加原打包费 / 堂食桌加打包商品 / 点餐加打包类商品 / 外卖桌走轮次点餐 | 任意 | 接口拒绝 |

## 11. 数据与判定（实施草案）

### 11.1 字段

| 表 | 新增 | 说明 |
|----|------|------|
| `restaurants.feature_flags` | `takeaway_ordering` | 总开关 |
| `restaurant_table_groups` | `is_takeaway boolean NOT NULL DEFAULT false` + 部分唯一索引 `(restaurant_id) WHERE is_takeaway` | 外卖组 |
| `menu_categories` | `is_packaging boolean NOT NULL DEFAULT false` + 部分唯一索引 `(restaurant_id) WHERE is_packaging` | 打包类 |
| `menu_items` | `takeaway_enabled boolean NOT NULL DEFAULT false`、`takeaway_price numeric NULL`（check：enabled 时 > 0） | 可外卖 |
| `table_sessions` | 开台渠道字段（名称实施时定，如 `ordering_channel`：`dine_in` \| `takeaway`，NOT NULL DEFAULT `dine_in`） | 开台时写入；有会话时菜单、价格、出单、重打、营收**只认此字段**；转台/并台仅同渠道，故不变 |
| `analytics_daily_restaurant_stats` 等日统计 | 增加渠道维度（加列或扩主键，实施时定）；历史行补为堂食 | 营收拆分（§9）；现主键为 `(restaurant_id, business_date)` |

不改 `restaurant_tables`。「总开关开 **且** 桌在外卖组」只在**开台时**和**无会话浏览菜单时**使用；开台后一律看会话渠道。

### 11.2 唯一判定点

| 判定 | 唯一来源 |
|------|----------|
| 桌台的点单渠道（菜单、外卖价、出单标记、重打、营收） | 唯一函数（如 `resolveTableOrderingChannel`）：**有会话 → 会话渠道字段**；无会话 → 总开关开 **且** 桌台属于 `is_takeaway` 分组。开台写入渠道也调用它。客户端、服务端、打印、统计不另写第二份判断 |
| 外卖菜单可见 + 价格 | 客户端 `resolveCustomerMenuCatalogView`（加渠道参数）与服务端 `resolveAppendCartItems` 共用同一定价/可见性函数 |
| 打包商品不进菜单 | 同一 catalog view 排除 `is_packaging` 类别；`resolveAppendCartItems` 同样拒绝 |
| 打包行不算菜 | 新 `OrderItemKind 'packaging'`；`isMenuCatalogItem` 排除 → 厨房屏、楼面待出餐、菜品历史、排行、点评、寿司限量一次性排除，且不依赖档口配置 |
| 客人可点单门槛 | 与现行一致：会话 `open` 即可加单（外卖开台不写自助餐行） |

## 13. 实施前待核实（不影响需求，影响实现）

1. **开台小票二维码打印**：当前打印 payload 无二维码字段；需在 farvoo-fatura 确认 Print Agent 是否支持 ESC/POS 二维码，或需新增。
2. **出品单「外卖」标记**：需确认 farvoo-fatura 档口小票模板如何显示。
3. **分单中的打包行**：核实现有打包费行在按菜分单、客人已呼叫后追加时的规则，打包商品行沿用。
4. **转台 / 并台 RPC**：在 `transfer_table_session` / `merge_*` 中校验「仅同为外卖组内桌，或同为堂食」的位置。
5. **营收 UI**：已定「分段筛选 + 全部时对比行（只拆已收）」，本期实施（见 §9 与 `docs/design/instore-takeaway-revenue-mock.html`）。
6. **营收拆分数据链路**：首页营收汇总 RPC（`dashboard_overview_revenue_bundle`）、区间营业额、日统计写入、增值分析查询各自如何带渠道；日统计表加列还是扩主键。
