# 开台弹窗可开套餐加载（防闪屏 + 版本缓存）

日期：2026-11-08  
分支：`fix/open-table-sheet-flash`  
UAT 基址：`http://localhost:3001`（`MESA_NEXT_DIST_DIR=.next-uat`）

## 本次修改

- 可开套餐列表或单价未齐时，开台编辑区只显示加载文案，不画空选择区 / 半成品价。
- 可开列表 + 默认选中 + 可见套餐单价都齐了，才一次画出完整表单。
- 看板预取可开套餐列表。
- 客户端按 `buffet_config_version` + 当前时段 `slot_key` 做 ensure（与顾客菜单 catalog 同模式）：有缓存先画，版本与时段都未变则 `{ unchanged: true }`，不反复拉全量 ids。
- 后台改套餐 / 时段 / 规则 / 日历 / 周五策略后 bump `buffet_config_version`。
- 涉及：`WaiterBuffetPackagesEditor`、`WaiterDisplay`、`WaiterBoardOpenTableSheet`、`WaiterBoardOpenTableForm`、`useWaiterOpenableBuffetIds`、`waiter-buffet-openable-client-cache`、`buffet-config-version`、`buffet-openable-server`、GET `…/staff/waiter/buffet`、迁移 `20261108120000_buffet_config_version.sql`。

## 核心业务规则

1. 开台选套餐界面只有两种：加载中，或完整定稿表单（套餐单选 + 单价 + 人数 + 预计合计）。
2. 单价文案只出现最终结果，中间不得换成「正在查询价格」。
3. 「当前可开哪些套餐」仍以 `GET …/staff/waiter/buffet` 为准；服务端开台校验不变。
4. 有本地缓存时进入看板 / 弹窗先用缓存 ids 画；ensure 比对 version + slot，双匹配则不换列表。
5. 外卖台锁人数路径不依赖可开列表加载。

## 详细测试场景

### 场景 1：点空桌开台（定稿一帧）

- **前置状态**：服务员已在楼面看板。
- **操作过程**：点空桌打开开台弹窗；连续抓弹窗文案。
- **预期结果**：完整表单出现后，单价行不再变成「正在查询价格」；不会先「无匹配价格」再跳成真价。
- **数据验证**：无需写库。
- **异常恢复**：取消关闭即可。

### 场景 2：可开列表或单价未齐时点开台（冷缓存）

- **前置状态**：可开套餐或单价请求尚未返回；本地无 openable 缓存。
- **操作过程**：点空桌打开开台弹窗。
- **预期结果**：弹窗内只有加载文案 + 取消 / 禁用确认；没有半成品价或空选择区。
- **数据验证**：齐了之后同一弹窗一次变为完整表单。
- **异常恢复**：可点取消关闭。

### 场景 3：可开列表 API（全量）

- **前置状态**：已登录有开台权限的账号；不带 knownVersion。
- **操作过程**：`GET /api/restaurants/{slug}/staff/waiter/buffet`。
- **预期结果**：200，返回 `buffet_ids`、`version`、`slot_key`。
- **数据验证**：与看板开台可选套餐一致。

### 场景 4：版本未变 → unchanged

- **前置状态**：已拿到一次全量响应的 `version` + `slot_key`。
- **操作过程**：同账号再请求 `?knownVersion=…&knownSlotKey=…`。
- **预期结果**：200，`unchanged: true`，无 `buffet_ids`；客户端继续用缓存 ids。
- **数据验证**：本地 `buffet_config_version` 与响应 `version` 一致。

### 场景 5：缓存热启动看板再开台

- **前置状态**：本机已有该店 openable 缓存（刚进过看板）。
- **操作过程**：刷新看板后立刻点空桌开台。
- **预期结果**：弹窗尽快出现完整套餐选择（不因可开列表冷拉而长时间只显示加载）；单价仍一次定稿。
- **数据验证**：Network 中第二次 buffet GET 可为 unchanged。

## 风险与待确认

- 可开列表请求失败且无缓存时 hook 仍把状态留在 `null`，界面会一直停在加载（原有问题）。
- 跨时段边界：slot 变了会强制全量；未另做定时器，靠进入页面 / 打开弹窗时 ensure。
