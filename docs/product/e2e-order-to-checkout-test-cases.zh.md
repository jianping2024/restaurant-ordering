# 点餐 → 结账 · 全场景测试用例

> **用途：** 覆盖一桌从开台、点餐、分单、收款到关台的完整路径；含三种分单、恢复点单续结、顾客手机与员工端并发。  
> **口径来源：** `[03-user-flows.md](./03-user-flows.md)`、`[04-business-rules.md](./04-business-rules.md)`、`[by-item-collect-payment.zh.md](./by-item-collect-payment.zh.md)`、`[../checkout-resume-ordering.zh.md](../checkout-resume-ordering.zh.md)`、`[../guest-individual-checkout.zh.md](../guest-individual-checkout.zh.md)` §15。  
> **用法：** 每条记 **pass / fail**；布局/金额类须看屏或量测，不能只凭「有文案」。`skip` 仅当真阻塞（无桌、无店、无权限）并写原因。  
> **与日更 UAT 的关系：** 某日合入改动的专项清单见 `docs/uat-YYYY-MM-DD-*.zh.md`；本文是常驻全链路回归底稿。

## 0. 前置与记分

### 0.1 环境


| ID     | 前置                             | 期望                          |
| ------ | ------------------------------ | --------------------------- |
| ENV-01 | 本地 web 可达；本地 Supabase ready    | `/api/health/live`、ready 正常 |
| ENV-02 | 员工账号有楼面 + 结账权限                 | 能开台、进结账台收款                  |
| ENV-03 | 测试店有桌台；有至少一种上架菜；建议有自助餐套餐       | 可开台写人数；无自助餐时标注相关条 `skip`    |
| ENV-04 | 顾客端：两台浏览器/两个隐身窗（模拟两部手机）+ 员工端一窗 | 可测并发；手机视口约 390×844          |
| ENV-05 | 打印 / 开票（可选）                    | 无 agent 时打印条目标 `skip` 并写原因  |




### 0.2 角色与入口


| 角色         | 入口                                                           |
| ---------- | ------------------------------------------------------------ |
| 顾客手机 A / B | 扫码或 `/{slug}/menu?table_id=…` → 账单 `/{slug}/bill?table_id=…` |
| 员工楼面       | `/dashboard/waiter` → 桌台详情                                   |
| 员工结账台      | `/dashboard/checkout`（列表 + 详情）                               |




### 0.3 分单模式（顾客账单芯片）


| 模式                | 顾客行为                  | 呼叫后会话                     |
| ----------------- | --------------------- | ------------------------- |
| `whole_table`（默认） | 整桌一笔应付                | 整桌计划 → 会话进入结账态（`billing`） |
| `even`            | 填人数名单，金额均摊            | 同上，整桌共享计划                 |
| `by_item`         | 本机填一次名字 + 认领份数；一机一人一票 | **按票**呼叫：不锁整桌；他人可继续点菜/认领  |


员工楼面「呼叫结账」走 `ensure-entry`：有活跃分单则沿用，没有则 mint 整桌。

## 1. 主路径：开台 → 点餐 → 整桌结账 → 关台


| ID    | 场景      | 步骤                                                | 期望                                           |
| ----- | ------- | ------------------------------------------------- | -------------------------------------------- |
| P1-01 | 冷开台     | 空闲桌 → 选自助餐（若有）→ 成人数≥1 → 确认开台                      | 会话 `open`；桌卡变用餐中；顾客菜单可点                      |
| P1-02 | 顾客点菜    | 手机加 2～3 道菜 → 提交                                   | 订单写入；底栏进已点态；厨房侧可见（有厨房权限时）                    |
| P1-03 | 同桌第二部手机 | 手机 B 打开同桌菜单                                       | 可见菜单；他人新下单可侧边飘窗（约 10s 渐隐）                    |
| P1-04 | 看账单     | 手机 A「查看账单」                                        | 明细与金额与已点/纸面账单口径一致（`billableLineAmount>0` 的行） |
| P1-05 | 整桌呼叫    | 选「整桌」→ 呼叫结账                                       | 分单 `requested`；会话 `billing`；菜单不可再加菜；结账台出现该桌  |
| P1-06 | 员工收款    | 结账台打开该桌 → 收款 → 选付款方式（现金/刷卡/混合）→ 确认                | 台账有一笔；待收归零；会话关闭；桌空闲                          |
| P1-07 | 顾客收齐面   | 收齐关台后看手机 A                                        | 停在已结清/感谢面，**不**自动跳回可点菜单                      |
| P1-08 | 员工代呼叫   | 会话 `open`、有消费 → 桌台详情「呼叫结账」（`quick_table_close` 关） | 进结账台；有活跃分单则 reopen，无则整桌                      |

## 2. 点餐变体（结账前）


| ID    | 场景              | 步骤                           | 期望                                  |
| ----- | --------------- | ---------------------------- | ----------------------------------- |
| OR-01 | 未开台点餐           | 空闲桌扫码菜单                      | 不可提交；提示需开台                          |
| OR-02 | 结账中加菜           | 整桌/均摊已呼叫（会话 `billing`）→ 菜单加菜 | 拒绝；提示去账单/等待                         |
| OR-03 | 员工代点            | 楼面代点入口加菜                     | 订单写入；与顾客点单同会话                       |
| OR-04 | 改开台人数           | 用餐中改成人/儿童                    | 自助餐基准行重算；菜单行厨房状态不动                  |
| OR-05 | 楼面减菜            | 未结账 → 桌台详情减份至 0              | 行 void/减量；金额刷新；`buffet_base` 不可靠减菜删 |
| OR-06 | 寿司轮次（若店为 sushi） | 免费菜入篮 → 送厨本轮 → 冷却后再点         | 一轮一次写单；冷却期内规则见 sushi 定稿；收费菜走加菜路径    |
| OR-07 | billing 中改人数    | 结账台详情改人数（有自助餐）               | 允许 `intent=save`；结账单金额刷新；不加菜        |

## 3. 分单 · 整桌（`whole_table`）


| ID    | 场景       | 步骤                     | 期望                                           |
| ----- | -------- | ---------------------- | -------------------------------------------- |
| WT-01 | 默认芯片     | 首次进账单                  | 默认「整桌」                                       |
| WT-02 | 呼叫成功     | 有消费 → 呼叫               | 进入等待收款；两部手机都进提交成功/等待面                        |
| WT-03 | 零人数呼叫    | 开台人数 0 → 顾客/员工呼叫       | **不**因人数失败；员工进详情且店有自助餐时弹零人数软确认               |
| WT-04 | 同行组多桌    | 桌在同行组且组内 >1 桌 → 呼叫     | 禁用/失败 `party_merge_required`；并桌或移出至剩 1 桌后可呼叫 |
| WT-05 | 未收款恢复    | 呼叫后未收款 → 员工「恢复点单」      | 会话回 `open`；可再点菜；可改分单模式                       |
| WT-06 | 整桌已收禁止恢复 | 整桌收齐后（或业务上整桌已结清）→ 恢复点单 | 禁止（`whole_table_paid`）                       |
| WT-07 | 草稿刷新     | 未呼叫前改模式/刷新页            | 本机草稿可恢复；呼叫成功后不再用本地草稿压服务端                     |

## 4. 分单 · 均摊（`even`）


| ID    | 场景      | 步骤                            | 期望                                    |
| ----- | ------- | ----------------------------- | ------------------------------------- |
| EV-01 | 两人均摊    | 选均摊 → 两人姓名 → 呼叫               | 两人应付之和 = 消费总额（分币规则内）；结账台两人「本次应收」      |
| EV-02 | 人数边界    | 人数 0 / 空名                     | 不可呼叫；校验提示                             |
| EV-03 | 逐人收款    | 先收客人 1 → 再收客人 2               | 每人台账独立；全员付清后关台                        |
| EV-04 | 部分收款后恢复 | 只收 1 人 → 恢复点单                 | 已收台账保留；分单模式锁定；可继续加菜后再结                |
| EV-05 | 有收款改人数  | 部分已收 → 试图改均摊人数/模式             | 模式锁定；不可换成整桌/按菜                        |
| EV-06 | 员工均摊编辑  | 员工 ensure-entry 后切均摊（未收款整桌可切） | 默认人数按产品（员工端均摊 min/default 见结账壳）；可提交再收 |
| EV-07 | 折扣后均摊   | 未收款 → 打折 → 看各人本次应收            | 折后义务按一人切开一次；确认收款认折后本次应收               |

## 5. 分单 · 按菜（`by_item`）



### 5.1 顾客手机（一机一人一票）


| ID     | 场景       | 步骤                           | 期望                                           |
| ------ | -------- | ---------------------------- | -------------------------------------------- |
| BI-G01 | 认领界面     | 选按菜                          | 先填一次名字；每道菜认领份数（1 / ½ / ⅓ / ¼ / ⅕）；可「全部认领」    |
| BI-G02 | 部分认领呼叫   | 只认领一部分菜 → 呼叫结账               | 成功；**整桌不锁**；会话保持可点（他人仍可点菜/认领）                |
| BI-G03 | 本机占用     | 呼叫后回菜单                       | 本机不可再点；待结账/占用提示                              |
| BI-G04 | 他人只读叠加   | 手机 A 已认领/已呼叫 → 手机 B 打开按菜     | 别人的认领只读可见；可认领剩余；超额标红不可呼叫                     |
| BI-G05 | 未付重名     | 手机 B 用与 A 相同的未付/待结账名         | 拒绝（名字已被本桌使用）                                 |
| BI-G06 | 已付可同名新票  | A 付清 → A 再点菜 → 新票            | 新 `party_id`；名字可预填可改；可再呼叫                    |
| BI-G07 | 分数份      | 一道菜 1 份 → A 认 ½、B 认 ½ → 双方呼叫 | 池分完；金额按份额算法；员工可分别收款                          |
| BI-G08 | 自助餐人头    | 有成人/儿童基准 → 认领「几个大人/小孩」       | 与菜池人头剩余一致；超额不可呼叫                             |
| BI-G09 | 本机草稿     | 填名认领后刷新未呼叫                   | 本机草稿恢复；不整桌覆盖别人的票                             |
| BI-G10 | 员工解锁本机票  | 已呼叫未收款 → 员工份额区「恢复点单」解锁 → 顾客机 | 本机票退回可编辑；本机可再点；他人不受影响；客人手机无「恢复点单」 |
| BI-G11 | 池未分完关台门禁 | 仍有未认领菜 → 员工试图关台/收齐关台         | 未分配未付清时关台按现有整桌应收−已收规则；不新增「还有 N 份」专用弹窗（与定稿一致） |




### 5.2 员工结账台（人轨 + 池）


| ID     | 场景      | 步骤                     | 期望                                      |
| ------ | ------- | ---------------------- | --------------------------------------- |
| BI-S01 | 工作台结构   | 打开按菜结账单                | 人轨（名+€+已收✓）+ 池剩余 + 当前人份额；账单汇总在 sticky 条 |
| BI-S02 | 池未分完收款  | 只分一部分 → 对当前人收款         | 弹窗本次应收 = 该票折后应付 − 该票已收；**不**被摘要「待收」夹断   |
| BI-S03 | 确认只写本票  | 多人未付 → 收票 A            | 只核/只写 A；其它票应付/份额不变                      |
| BI-S04 | 已付票只读   | A 已收 → 试图往 A 叠菜或改 qty  | 不可；同人续消费须新票（可同名）                        |
| BI-S05 | 串行下一票   | 收完当前未付 → 池仍有剩余         | 自动/可 mint 下一未付芯片；无平行「+添加人员」（按菜工作台）      |
| BI-S06 | 员工解锁票   | 顾客已呼叫未收款 → 员工解锁该票      | 票回未呼叫；顾客可再编辑；队列票状态更新                    |
| BI-S07 | 删除份额不诈尸 | 员工删未付份额行 → Realtime/刷新 | 不因服务端 persons 同种子复活；omit 生效             |
| BI-S08 | 权威变侧重灌  | 客人再呼叫合并方案 → 员工屏        | 未付 draft 以服务端当前桌单为准重灌；职员本机脏未付不压住新方案     |
| BI-S09 | 恢复点单门禁  | 按菜有未付默认串号名「客人 N」→ 恢复   | 先清无名无份额人，仍剩默认名则提示改名并中止                  |
| BI-S10 | 空份额隐藏收款 | 当前人无有效份额               | 空态文案；隐藏估计/收款                            |




### 5.3 按菜续结


| ID     | 场景     | 步骤                                                    | 期望                           |
| ------ | ------ | ----------------------------------------------------- | ---------------------------- |
| BI-R01 | 零收款解锁  | 按菜呼叫后零收款 → 员工份额区「恢复点单」（解锁票） | 该票退回可编辑；本机可再点/再呼叫；**无**会话脚恢复 |
| BI-R02 | 部分收款后  | A 已收、B 未收 → 解锁 B → 加菜              | 已收台账不丢；A 份额只读；新菜只能分给未付票；不可解锁已付票 |
| BI-R03 | 再呼叫合并  | 续点后顾客/员工再交方案                       | 已付票金额不被 merge 改写（含 1¢）；未付可更新 |
| BI-R04 | 员工接管   | 员工 ensure-entry / 收款路径盖 `staff_checkout_requested_at` | 队列不因「票都付清但池未分完」而消失；按菜页无会话脚「恢复点单」，份额区票级按钮文案仍是「恢复点单」 |

## 6. 收款、折扣、付款方式


| ID     | 场景     | 步骤                     | 期望                                            |
| ------ | ------ | ---------------------- | --------------------------------------------- |
| PAY-01 | 现金     | 收款选现金 → 实收≥应收 → 确认     | 台账 `CASH`；找零正确；有现金时开钱箱（有 agent）               |
| PAY-02 | 刷卡     | 选刷卡                    | 台账 `MULTIBANCO`；无拆额                           |
| PAY-03 | 混合     | 卡额改小使现金>0 → 确认         | 台账 `MIXED` + `payment_lines` 两行；两边都必须 >0      |
| PAY-04 | 折扣     | 未收款 → 打折 + 原因          | SettlementBar / 人芯片 / 弹窗同一折后视图；高折扣进异常审计       |
| PAY-05 | 有收款后折扣 | 已有台账 → 改折扣             | 通常禁用或不可丢台账                                    |
| PAY-06 | 摘要待收   | 部分收款后看 sticky          | 待收 = 折后整桌应收 − 已收合计（不是 Σ 人 outstanding 的第二套算法） |
| PAY-07 | 重复收同一人 | 对已付 `person_index` 再确认 | `409 already_paid`（或等价）                       |
| PAY-08 | 零人数软确认 | 有自助餐、人数 0 进结账详情        | 弹一次；确认后本单不再弹；可改人数                             |

## 7. 并发 · 顾客手机 × 顾客手机


| ID    | 场景           | 步骤                           | 期望                                          |
| ----- | ------------ | ---------------------------- | ------------------------------------------- |
| CG-01 | 同时点菜         | A、B 同时提交不同菜                  | 两单都进会话；双方菜单/已点最终一致（Realtime 或回前台 reconcile） |
| CG-02 | 同时认领同菜超额     | 剩 1 份 → A、B 几乎同时各认 1         | 一方成功一方冲突/超额失败；池最终不超分                        |
| CG-03 | 先后按票呼叫       | A 呼叫后 B 仍点菜并呼叫               | A 占用本机；B 成功；桌不因 A 进入整桌 `billing` 锁死         |
| CG-04 | A 呼叫时 B 在账单页 | A 呼叫 → B 停留可见页               | B 收到通知（弹框/静默刷新按产品）；B 菜池更新                   |
| CG-05 | 整桌呼叫互斥       | A 选整桌呼叫成功 → B 再呼叫            | B 见已提交/等待面或拒绝重复；不可再改分单                      |
| CG-06 | 均摊共享计划       | A 填均摊呼叫 → B 打开账单             | B 看到同一等待面；不可各搞一套均摊                          |
| CG-07 | 付清后新票        | A 付清再点 → B 仍有未付票             | A 新票与 B 未付票并存；身份靠 `party_id` 不撞车            |
| CG-08 | 清缓存换机        | A 清 localStorage 再进 → 用旧未付同名 | 提示换名或请员工协助；不能冒用他人未付票                        |

## 8. 并发 · 顾客手机 × 员工端


| ID    | 场景                      | 步骤                            | 期望                                                 |
| ----- | ----------------------- | ----------------------------- | -------------------------------------------------- |
| CS-01 | 顾客呼叫 → 员工自动进结账          | 员工停在该桌详情 → 顾客呼叫               | Toast + 自动进 `/dashboard/checkout?table_id=…`       |
| CS-02 | 员工改人数 ↔ 顾客账单            | 顾客停在账单 → 员工改开台人数              | 顾客金额/人头刷新（Realtime/门铃全量 sync，非轮询）                  |
| CS-03 | 员工编辑未付 ↔ 顾客再呼叫          | 员工正在改按菜 draft → 顾客交新票         | 员工权威指纹变 → 未付 draft 重灌服务端方案；已锁票不动                   |
| CS-04 | 顾客呼叫后员工改票再收款            | 顾客已呼叫 → 员工改份额（没收款前允许）→ 收款     | 弹窗金额与确认时校验一致；认弹窗金额入账                               |
| CS-05 | 员工收款 ↔ 顾客待结账页           | 员工确认该票收款 → 顾客页可见              | 该票已收；付清后可开新票；隐藏窗格下至少「回到前台后状态正确」                    |
| CS-06 | 员工恢复点单 ↔ 顾客             | 整桌/均摊 `billing` → 员工恢复 → 顾客菜单 | 顾客可再点；已收不丢                                         |
| CS-07 | 按菜员工解锁 ↔ 顾客             | 员工解锁顾客票 → 顾客机                 | 顾客可编辑/可点；占用解除                                      |
| CS-08 | 员工 ensure-entry 与顾客整桌草稿 | 顾客未呼叫、本地有草稿 → 员工呼叫结账          | 员工沿用/生成服务端计划；以服务端为准进入结账                            |
| CS-09 | 结账中顾客扫码加菜               | 整桌 `billing` → 顾客加菜           | 拒绝                                                 |
| CS-10 | 按菜他人加菜                  | A 已按票呼叫 → B 或员工代点加菜           | 允许（桌未整桌锁）；新菜进池供未占用手机/员工分配                          |
| CS-11 | 转台/并台                   | 有已呼叫按票或 `billing` → 转台/并台     | 拦截（有活跃结账占用时）                                       |
| CS-12 | 楼面减已认领菜                 | 某份已被票占用 → 减菜/void             | 失败并提示被票占用（`claimed_by_ticket`）                     |
| CS-13 | `quick_table_close` 开   | 开关开 → 楼面「关台结账」；顾客仍可呼叫         | 员工 ensure-entry 不可用；顾客手机呼叫仍可用；与打印发票开关互斥            |
| CS-14 | 关台结账 vs 顾客中途呼叫          | 员工点关台结账同时顾客呼叫                 | 一方成功一方失败或会话最终一致关闭/结账；无双重关台脏数据（查 session 唯一 closed） |

## 9. 并发 · 员工 × 员工


| ID    | 场景         | 步骤                                              | 期望                                        |
| ----- | ---------- | ----------------------------------------------- | ----------------------------------------- |
| ST-01 | 双人同时收不同人   | 均摊/按菜两人未付 → 两名收银对 `person_index` 0 与 1 **同时**确认 | 两行均 `paid`；无丢失更新；全员付清只关台一次                |
| ST-02 | 双人同时收同一人   | 两人同时确认同一 `person_index`                         | 一成功一 `already_paid`                       |
| ST-03 | 双开同一结账详情   | 两浏览器打开同一桌结账 → 一方收款                              | 另一方刷新后见已收；待收一致                            |
| ST-04 | 一方恢复一方收款   | A 点恢复点单、B 同时确认收款                                | 最终会话与台账一致；不得出现「已收丢失」或「已关台仍 open」          |
| ST-05 | 强制关台 vs 收款 | 一方强制关台、一方收款                                     | 未付 split→`cancelled` 或收款先成功再关；订单保留；已收台账保留 |

## 10. 关台与异常收尾


| ID    | 场景     | 步骤                      | 期望                                   |
| ----- | ------ | ----------------------- | ------------------------------------ |
| CL-01 | 正常付清关台 | 待收 0                    | 会话 `closed`；分单 `paid`；桌空闲            |
| CL-02 | 强制关台   | 有未付 → 强制关台确认            | 会话关闭；未付分单 `cancelled`；已收保留；不计正常营业额路径 |
| CL-03 | 空会话结账  | 无消费呼叫                   | `empty_session` 或等价拒绝                |
| CL-04 | 重复呼叫   | 已 `billing` 再整桌 request | `409 session_billing`（须先恢复或完成）       |
| CL-05 | 结账台空队列 | 收完最后一单后                 | 曾有过待结单则自动回楼面；冷打开空队列则留在结账台空态          |
| CL-06 | 取消回桌台  | 结账详情「取消」                | 回该桌详情；队列该单仍在                         |
