# 本次改动业务场景测试报告 · 客人菜单按编码/名称定位

日期：2026-11-07  
分支：`feat/guest-menu-dish-search`

## 1. 本次修改

- **内容：** 客人点餐页顶栏下增加搜索框；按菜品编码或当前语言菜名匹配，点选后切分类并滚到菜卡短暂高亮。
- **文件：** `CustomerMenuDishSearch`、`guest-menu-dish-search`、`use-guest-menu-dish-locate`、`MenuOrderingController`、`SushiMenuPage`、`MenuItemCard`、`menu-recommended`（暴露 `servedItems`）、`menu-page-messages`、`globals.css`、sole 索引、设计稿。
- **角色 / 页面：** 客人经典菜单、寿司菜单；店员代点嵌入页同挂经典控制器。

## 2. 核心业务规则

1. 搜索不替代分类浏览：不整页过滤成结果列表。
2. 只匹配当前可见目录（通道 + 时段过滤后）且 `available` 的菜。
3. 匹配字段：`item_code` + 界面语言菜名；编码精确/前缀优先于菜名包含。
4. 定位：切顶分类、子分类「全部」、滚到菜卡、约 1.2s 金边高亮；不自动打开详情。
5. 输入框唯一用 `Input` clearable；清空后恢复正常逛菜单。

## 3. 详细测试场景

### 场景 1：按编码定位（正常）

- **前置：** 开台会话；菜单有带编码菜（如 A12）；客人打开点餐页。
- **操作：** 在搜索框输入编码前缀或完整编码 → 点建议行。
- **预期：** 建议出现该菜；点后框清空；左轨切到该分类；列表滚到该菜并短暂高亮。
- **数据：** 无写库；仅客户端导航。
- **恢复：** 高亮消失后可继续点 `+` / 开详情。

### 场景 2：按菜名定位

- **前置：** 同上；界面语言中文。
- **操作：** 输入菜名部分字 → 点建议。
- **预期：** 命中含该字的可见菜；定位行为同场景 1。

### 场景 3：无结果

- **前置：** 同上。
- **操作：** 输入不存在的编码（如 ZZ99）。
- **预期：** 提示「没有找到相关菜品」；分类与列表不变；不清空也不跳转。

### 场景 4：清空 ×

- **前置：** 搜索框有字且建议打开。
- **操作：** 点 ×。
- **预期：** 输入清空；建议关闭；菜单仍可逛。

### 场景 5：跨分类定位

- **前置：** 当前在分类 A；目标菜在分类 B。
- **操作：** 搜到分类 B 的菜并点选。
- **预期：** 左轨切到 B；列表显示 B 的菜并高亮目标。

### 场景 6：回归 · 分类浏览与加菜

- **前置：** 定位完成后。
- **操作：** 再点左轨其他分类；对某菜点 `+` 或开详情。
- **预期：** 分类切换与加菜仍正常；无搜索残留挡住操作。
