# 口味分组 + 浇头关联（点单配置）

店员给主菜挂「点单时必须/可选的配置」；与 **风味提示**（只展示）和 **预选备注**（选填文案）分开。

## 口味分组

- 全店共用字典：`menu_choice_groups` + `menu_choice_options`（三语文案）
- 菜品 `choice_bindings`：`[{ group_id, option_ids[] }]`，勾要用的分组与选项
- 顾客：每个挂上的分组 **单选、必选一**
- 无价格；结果进主菜行备注/选项快照（跟厨可见）

## 浇头

- 菜品 `topping_binding`：`{ category_id, item_ids[], required }` 或 `null`
- **挑选一个类别**，再勾该类下的菜；`item_ids` 空 = 该类全部
- `required`：顾客是否必须至少选一种（可改数量）
- 浇头是真菜，主菜单可单独点；有价，下单时展开为独立行（或等价进单）

## 点餐交互

- 未挂口味且未挂浇头：列表可直接加减
- 挂了任一：列表加号进详情，必选未完成不能加入
- 购物袋分行：主菜 + 口味选择 + 浇头组合（含数量）+ 备注（预选+手写）全部相同才叠份
- **展示：** 购物袋行下只读口味摘要 + 已选浇头（名/份数/价）；顾客「已点」与店员桌台详情「已点」行下展示该行说明（口味文案 + 备注）。浇头下单后仍是独立行。桌台详情列表：同一菜同一说明才叠份（收钱合计仍按原计价合并，不看说明）

## 明确不做

- 不用 `flavor_codes` 充当点单选项
- 不用预选备注充当口味组/浇头
- 不为无价口味建假菜
- 浇头不一次列出全店所有类别；先选一个类别再勾菜
