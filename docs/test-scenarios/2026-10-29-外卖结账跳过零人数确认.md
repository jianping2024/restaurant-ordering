# 本次改动业务场景测试报告 — 外卖结账跳过零人数确认

## 1. 本次修改

- **内容：** 外卖会话进结账详情时，不再弹出「开台人数为 0，是否确认？」／「调整人数」。堂食有自助、人数为 0 时仍弹。
- **文件：** `checkout-zero-headcount-prompt.ts`（+ 单测）、`CheckoutRequestDetailHost.tsx`；产品文档 `02-feature-map` / `03-user-flows` / `04-business-rules` / `e2e-order-to-checkout-test-cases` / `instore-takeaway.zh.md`
- **角色 / 页面：** 收银结账台详情（员工）
- **唯一写法：** `shouldPromptCheckoutZeroHeadcount` 入参含会话渠道；`takeaway` → 不弹。渠道优先用桌台详情 `sessionMeta.orderingChannel`（与自助套餐同一份），避免第二路查询把外卖盖成堂食。

## 2. 核心业务规则

1. 【本次新增】结账详情零人数软确认只对**堂食**会话生效。
2. 【已实现】外卖开台人数固定为 0、不按人数收费；结账不因人数弹窗。
3. 【已实现】堂食：店有启用自助套餐且人数为 0 → 弹一次；确认后本单不再弹；可选调整人数。
4. 【已实现】呼叫结账本身仍不因人数为 0 拦截（堂食 / 外卖）。

## 3. 详细测试场景

### 场景 1：外卖桌结账进详情 — 不弹零人数

- **前置状态：** 白云有启用自助；A-20 外卖会话 `billing`，结账单 `13e999d9-…`。
- **操作过程：** 员工打开结账详情（`:3002`，清 SW 后硬进页）。
- **预期结果：** 不出现「开台人数为 0，是否确认？」；可见「+ Embalagem」。
- **数据验证：** 会话 `ordering_channel=takeaway`。
- **标签：** 【已验证】

### 场景 2：堂食零人数结账 — 仍弹软确认（回归）

- **前置状态：** A-01 堂食开台人数 0；加菜 Chá Jasmin；`ensure-entry` 得结账单。
- **操作过程：** 打开结账详情。
- **预期结果：** 弹出「O numero de pessoas e 0. Confirmar mesmo assim?»；底栏为「+ Take away」（非耗材）。
- **标签：** 【已验证】

### 场景 3：唯一 gate 单测

- **说明：** `takeaway` → false；`dine_in` + 有自助 + 未确认人数 → true。
- **标签：** 【已验证】

### 场景 4：操作顺序 — 渠道晚到也不留窗

- **说明：** 实现上：`shouldPrompt` 为 false 时关掉已开的确认/调整窗；桌台模型渠道优先于可能失败的 client select。
- **标签：** 【已验证】（含在场景 1 修竞态后复测）

### 场景 5：并发 / 多终端

- **说明：** 本改动仅为进详情是否弹窗，无写冲突。
- **标签：** 【不适用】
