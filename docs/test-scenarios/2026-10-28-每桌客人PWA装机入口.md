# 本次改动业务场景测试报告 — 每桌客人 PWA 装机入口

日期：2026-10-28  
分支：`feat/guest-table-pwa-manifest`  
UAT base：`http://localhost:3004`（feature · `MESA_NEXT_DIST_DIR=.next-uat-gtpwa4`）

## 1. 本次修改

- **内容**：顾客点餐页「添加到主屏幕」使用本桌启动链接；员工壳仍进 `/dashboard`。
- **文件**：`site-manifest.ts`（`buildGuestTableManifest`）、`guest-table-pwa-manifest.ts`（路径+URL）、`mesa-pwa-guest-table.webmanifest/route.ts`、`[slug]/menu/page.tsx`、`middleware-session-policy.ts`、设计文档与 sole 索引。
- **角色 / 页面**：客人 `/{slug}/menu?table_id=…`；店员默认 `/manifest.webmanifest`。
- **流程**：在本桌点餐页装机 → 冷启动直达本桌点餐（不登录）。

## 2. 核心业务规则

1. 客人点餐不要求员工登录；装机入口不得指向 `/dashboard`。
2. 每桌 `start_url` 唯一写法：`guestTableMenuStartUrl` → `/{slug}/menu?table_id=<uuid>`。
3. Manifest HTTP 只接受校验后的 slug+table_id，服务端拼 `start_url`，不接受客户端任意 URL。
4. 员工默认 manifest 仍为 `start_url=/dashboard`；未登录进 `/dashboard` 仍跳登录。
5. `handle_links: not-preferred`（扫码不劫持进已装 App）。
6. 客人路径常量/URL 拼装不进客户端壳 SW 引用的 `site-manifest`（避免打包炸）。
