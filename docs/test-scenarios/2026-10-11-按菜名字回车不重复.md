# 本次改动业务场景测试报告：按菜名字回车不重复

日期：2026-10-11  
分支：`fix/guest-claim-enter-duplicate`  
UAT 基址：`http://localhost:3002`（功能分支，非 `:3000`）

## 1. 本次修改

- **内容**：顾客账单「按菜」的名字框，回车先把这一下按完，再收起键盘。名字仍只保存框里这一段字，不会因为回车再写一遍。
- **文件**：`apps/web/src/components/menu/GuestClaimPanel.tsx`
- **角色 / 页面**：顾客手机 · 账单页 · 结账方式「按菜」·「你的名字」
- **不动**：均摊改名、员工看板改名、认领份数、呼叫结账接口

## 2. 核心业务规则

1. 【本次新增】回车只收键盘。按键还没结束时名字框保持焦点；按键结束后失焦，底部「呼叫结账」再出现。
2. 【已实现】名字只由输入覆盖保存，回车不另写一份。
3. 【已实现】名字框有焦点时，底部栏藏起来；失焦后底部栏回来。
4. 【已实现】「全部认领」仍按剩余份数认到这张票，名字不变。

## 3. 详细测试场景

### 场景 1：打一个名字，敲一次回车

- **前置状态**：白云店 A-08 已开台，自助餐 2 成人 2 儿童，账单未呼叫结账。顾客在账单页选「按菜」，名字框为空。
- **操作过程**：顾客在名字框输入 `john`，敲一次回车。
- **预期结果**：框里仍是 `john`。键盘收起（框失去焦点）。底部「呼叫结账」出现。
- **数据验证**：名字只在这台手机的认领草稿里，没有呼叫结账，服务端没有新的结账请求。
- **异常恢复**：再点进名字框可以改字；刷新页面后未提交的名字按本机草稿规则保留或清空，不产生第二张票。

### 场景 2：名字本身就是两遍一样的字

- **前置状态**：同场景 1，仍在「按菜」。
- **操作过程**：名字框输入 `娜娜`，敲回车。
- **预期结果**：框里仍是 `娜娜`，不会被砍成 `娜`。回车过程中（按键还没松）焦点还在框里，字不变；松手后失焦，底部栏出现。
- **数据验证**：受控输入的值是 `娜娜`。
- **异常恢复**：失焦后再点「全部认领」，名字仍是 `娜娜`。

### 场景 3：回车之后认领仍可用

- **前置状态**：名字是 `娜娜`，自助餐还没认领（我的 0 成人 / 0 儿童）。
- **操作过程**：点「全部认领」。
- **预期结果**：这张票认下 2 成人 / 2 儿童，剩余为 0。底部呼叫金额变为整桌 €59.90。名字仍是 `娜娜`。
- **数据验证**：只改本机认领草稿，未点呼叫结账，服务端账单仍是开台时的自助餐行。
- **异常恢复**：未呼叫就关台，不留下待付票。

### 场景 4：真机软键盘（原报障）

- **前置状态**：顾客用手机打开同一账单页「按菜」。
- **操作过程**：输入 `john`，点键盘上的回车/完成。
- **预期结果**：框里仍是 `john`，不是 `johnjohn`；键盘收起，底部栏出现。
- **数据验证**：与场景 1 相同。
- **异常恢复**：同场景 1。
