# 本次改动业务场景测试报告 — 推荐栏悬停/按下/焦点

## 1. 本次修改

- **内容：** 顾客菜单推荐栏海报补上与列表菜卡同舒适度的交互：鼠标悬停抬起+阴影、按下微沉、键盘整卡焦点描边；**不做**指针倾斜。去掉会裁切抬起的外层 `overflow-hidden`，横滑行加上下内边距。
- **文件：** `CustomerRecommendedRail.tsx`、`apps/web/src/app/globals.css`（sole `.mesa-recommended-poster`）、`docs/agent-sole-index.zh.md`、`docs/design/02-layout-patterns.md`
- **角色 / 页面：** 顾客经典/寿司菜单推荐栏；店面预览与 demo 菜单同源组件
- **流程：** 浏览推荐 → 悬停/按下/Tab → 点开详情（行为不变）

## 2. 核心业务规则

1. 【本次新增】推荐海报悬停（仅支持 hover 的指针设备）：整卡上移约 4px + 阴影加深；图或 emoji 略浮；**无** rotate/倾斜。
2. 【本次新增】按下：微沉（translateY 1px + scale 0.99）。
3. 【本次新增】键盘 `focus-visible`：整张海报一圈描边（sole CSS，不再用 Tailwind ring 第二套）。
4. 【已实现】点海报仍只打开详情；无列表金色 `+`；不复用 `MenuItemCard` / `.mesa-menu-item-card`。
5. 【已实现】`prefers-reduced-motion: reduce` 时关闭抬起/按下位移。
6. 【已实现】素食角标仍在菜图左上角；横滑推荐栏仍可用。

## 3. 详细测试场景

### 场景 1：桌面悬停抬起（不歪）

- **前置状态：** 顾客打开有推荐菜的菜单（或 `/demo/menu`）；桌面鼠标。
- **操作过程：** 鼠标移到某张推荐海报上，不按下。
- **预期结果：** 海报上移、阴影加深；图略浮；卡面不出现倾斜/歪斜。
- **数据验证：** 无服务端写；仅 CSS。
- **异常恢复：** 移开鼠标后恢复常态。

### 场景 2：按下微沉

- **前置状态：** 同上。
- **操作过程：** 在海报上按下鼠标（或触控按住）不松。
- **预期结果：** 海报微沉；松手后若仍悬停则回到抬起，否则常态。
- **数据验证：** 无写库。
- **异常恢复：** 松手即可。

### 场景 3：键盘焦点整卡描边

- **前置状态：** 同上。
- **操作过程：** 用 Tab 聚焦到某张推荐海报。
- **预期结果：** 整卡可见描边；Enter/Space 仍打开详情。
- **数据验证：** 详情层打开；无重复提交。
- **异常恢复：** Tab 走开后描边消失。

### 场景 4：横滑不被抬起卡住

- **前置状态：** 推荐菜多于一屏宽度。
- **操作过程：** 在推荐栏区域左右横滑；中途可短暂悬停一张。
- **预期结果：** 仍可横滑；抬起阴影不被金底硬裁到难看（有上下内边距）。
- **数据验证：** 无写库。
- **异常恢复：** 不适用。

### 场景 5：点开详情回归

- **前置状态：** 推荐栏可见。
- **操作过程：** 点击一张推荐海报。
- **预期结果：** 打开该菜详情；无加点按钮出现在推荐海报上。
- **数据验证：** 详情菜名/价与海报一致。
- **异常恢复：** 关闭详情后推荐栏仍在。

### 场景 6：列表大菜卡 tilt 不受影响（回归）

- **前置状态：** 同一菜单页有列表菜卡。
- **操作过程：** 鼠标在列表菜卡上移动。
- **预期结果：** 列表卡仍可抬起并带指针倾斜；推荐栏仍不歪。
- **数据验证：** 两套 CSS 类分离（`.mesa-menu-item-card` vs `.mesa-recommended-poster`）。
- **异常恢复：** 不适用。

### 场景 7：减少动效

- **前置状态：** 系统开启「减少动态效果」。
- **操作过程：** 悬停/按下推荐海报。
- **预期结果：** 无抬起/微沉位移（焦点描边仍可有）。
- **数据验证：** CSS `@media (prefers-reduced-motion: reduce)`。
- **异常恢复：** 关闭系统设置后动效恢复。【未验证】（本机未切系统设置）
