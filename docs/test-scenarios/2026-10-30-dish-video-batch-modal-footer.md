## 1. 本次修改

- **内容**：`Modal` 增加可选 `footer`（滚动 body 外、固定底栏）；「批量生成动图」把取消/生成放进 `footer`；菜列表去掉嵌套 `max-h-[min(50vh,22rem)]`，中间区域只滚一条轴。
- **文件**：`apps/web/src/components/ui/Modal.tsx`、`apps/web/src/components/dashboard/DishVideoBatchModal.tsx`；设计规则与 sole 索引同步。
- **角色 / 页面**：店主或有菜单管理权限的员工 → 后台「菜单」→ 菜品列表 →「批量生成动图」。
- **流程**：打开弹窗 → 选效果 / 勾选 → 不滚动也能看见并点「生成」或「取消」。生成编码逻辑本身【未改】。

## 2. 核心业务规则（不变量）

1. 【本次新增】批量确认弹窗的取消/生成**只**通过 `Modal` 的 `footer` + `ModalConfirmActions` 钉在面板底，不进可滚动 `children`。
2. 【已实现】候选仍是：当前筛选 ∩ 有静图且无动图；已有动图不进列表。
3. 【已实现】一份共享效果；勾选后才能点生成；0 选中时生成钮禁用。
4. 【已实现】短确认类 Modal 不传 `footer` 时行为与改前一致（标题 + 可滚 children）。
5. 【已实现】中间 body 唯一滚动；列表不再自带第二层 max-h。

## 3. 详细测试场景

### 场景 1：长列表时脚钮常显（正常）

- **前置状态**：本地临时将 20 道「有静图有动图」的 `video_*` 置空（测后已从 storage 还原）；筛选「全部菜品」→ 候选 21。
- **操作过程**：点「批量生成动图（21）」；不滚脚钮区；用脚本滚 `.modal-scroll`。
- **预期结果**：打开后「取消」「生成（21）」完整可见；确认行不在 scroll body 内；列表 `max-height: none`；滚 body 后脚钮视口位置不变。
- **数据验证**：未点生成；测后 20 道动图 URL 已还原。
- **异常恢复**：取消关闭后可再开。

### 场景 2：全不选 → 生成禁用（边界）

- **前置状态**：弹窗已开，默认全选 21。
- **操作过程**：点「全不选」；再观察生成钮。
- **预期结果**：文案「已选 0 / 21」；生成钮 `disabled`，文案变为「生成」。
- **数据验证**：无编码请求。
- **异常恢复**：可点「全选」恢复（本轮未再点生成）。

### 场景 3：取消 / 关闭不写库（异常恢复）

- **前置状态**：弹窗打开。
- **操作过程**：点「取消」。
- **预期结果**：弹窗关闭；无批量进度。
- **数据验证**：测后 eligible 回到 1（还原动图后）。
- **异常恢复**：可再次打开。

### 场景 4：短 Modal 无 footer 回归（回归）

- **前置状态**：菜单列表有「删除」。
- **操作过程**：点某道「删除」，出现「确定删除」。
- **预期结果**：短确认无 `footer` 边框槽；确认行仍在 `.modal-scroll` children 内。
- **数据验证**：点取消/关闭，未删除。
- **异常恢复**：关闭后列表仍在。

### 场景 5：操作顺序 — 先改效果再关（顺序）

- **前置状态**：弹窗打开。
- **操作过程**：点「冰爽闪光」→「取消」→ 再开批量弹窗。
- **预期结果**：再开时默认效果回到「推近」（`aria-pressed=true`）。
- **数据验证**：无写库。
- **异常恢复**：同场景 3。
