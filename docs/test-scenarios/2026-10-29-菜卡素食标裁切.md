# 本次改动业务场景测试报告 — 列表菜卡素食标底部裁切

## 1. 本次修改

- **内容：** 列表菜卡「素食」绿标底部被 `overflow-hidden` 裁切。根因是 pill 嵌在菜名 2 行 clamp 槽内。改为菜名文字与素食标 **sibling**（结构拆分，非缩 padding 补丁）。
- **文件：** `MenuItemCard.tsx`、`menu-item-card-layout.ts` / `.test.ts`、`docs/product/menu-flavor-hints.zh.md`
- **角色 / 页面：** 顾客经典菜单 / 寿司菜单列表；员工「继续点餐」共用 `MenuItemCard`
- **唯一写法：** `MENU_ITEM_CARD_NAME_ROW_CLASS` + `MENU_ITEM_CARD_NAME_CLASS`（仅文字 clamp）+ `MENU_ITEM_CARD_VEGETARIAN_BADGE_CLASS`（22px / shrink-0 / leading-none）

## 2. 核心业务规则

1. 【本次修正】素食标必须完整可见（圆角与字形底部不被裁）。
2. 【已实现】素食标仍贴菜名旁；菜名文字仍最多 2 行省略。
3. 【本次修正】clamp / `overflow-hidden` 只作用在菜名文字节点，不包裹素食标。
4. 【已实现】风味带 / 底行价与金色 + 布局契约不变。

## 3. 详细测试场景

- **操作：** 打开顾客菜单列表，找到该卡。
- **预期：** 「素食」pill 完整，底边圆角与「素/食」下半截不被切。
- **标签：** 【未在本 VM 浏览器验证】— 见 §5 环境 blocker；契约由单测锁死。

### 场景 2：长菜名 + 素食标

- **预期：** 菜名仍 ≤2 行省略；标在旁 `shrink-0`，不被挤出卡片、不被 clamp。
- **标签：** 【未在本 VM 浏览器验证】

### 场景 3：非素食菜

- **预期：** 无素食标；菜名行高度仍为 2 行槽，邻卡对齐不跳。
- **标签：** 【未在本 VM 浏览器验证】
