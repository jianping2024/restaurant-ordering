# 本次改动业务场景测试报告 · 结账加收 Take away

日期：2026-10-23　分支：`feat/checkout-takeaway`（restaurant-ordering）+ `feat/billsync-open-price`（farvoo-fatura）

## 1. 本次修改

- **收银端（结账页）**【本次新增】：汇总栏「＋ Take away」按钮（整桌 / 按菜 / 均摊共用一个入口）→ 弹窗按行输入金额，名称固定 `TAKE AWAY (PAGA À PARTE).`、数量固定 1，可连续加多行；「本桌菜品」里每行 Take away 带 ×，点了直接删除（不弹确认）。
- **数据**【本次新增】：Take away 是本桌订单里的一行真实账单行（`orders.items` kind=`takeaway`，id `takeaway:<uuid>`），不是账单上的附加金额字段；只能由 `POST /api/restaurants/[slug]/checkout/takeaway` 写入（需 `checkout.confirm_payment`），删除走同一路由 `DELETE`（复用现有减菜作废 + 操作记录 + 已认领保护）。
- **税率**【本次新增】：`restaurants.takeaway_vat_rate`（默认 13），在「功能设置 → 结账 · Take away」修改。
- **发票**【本次新增】：每行 Take away 固定编码 `TAKEAWAY`、带 `open_price: true`，一行一行开，不合并；网页端和 farvoo-fatura Agent 的「同编码必须同价」校验只对两行都带 `open_price` 时放宽单价比较（名称、税率仍须一致）。
- **不是菜品**：厨房屏 / 出单 / 当日菜品 / 菜品排行 / 顾客评价 / 他人点单浮层都不出现 Take away（统一用 `isMenuCatalogItem` 判断）。
- **涉及角色 / 页面**：收银、老板（结账页、功能设置页）；服务员、厨房、顾客只读影响（不出现 / 账单里出现）。

## 2. 核心业务规则（不变量）

1. 不含 Take away 的账单：发票、小票、按人小票、结账页菜品行、总额、订单状态与改动前**完全一致**（隔离要求）。
2. 同一次「加入账单」重试只写一次（请求号幂等）。
3. Take away 计入消费 / 应收 / 待收，整单折扣照常作用。
4. 已付款或半付款客人名下的 Take away 不能删（与菜品同一套已认领保护）；未分配的可直接删。
5. 发票上每笔 Take away 单独一行，单价各自不同、数量 1、税率取餐厅设置；缺税率时整单失败（不默认）。
6. 关台后不能再加（只接受本账单所属的进行中场次）。

## 3. 详细测试场景

**场景 1：整桌结账加 3 笔 Take away**
- 前置：A-18 开台 2 位成人自助 + 菜 102 ×2（€43.80），收银进入结账（billing）。
- 操作：收银点「＋ Take away」，输入 0.10、0.20、0.30，加入账单。
- 预期：3 行，名称固定、数量 1；总额 €44.40。
- 数据验证：`orders.items` 3 行 kind=takeaway、item_status=done、added_at 递增；`bill_splits.total_amount = 44.40`。
- 异常恢复：网络重试同一请求号 → 仍是 3 行。

**场景 2：重复提交 / 非法输入 / 越权**
- 操作：同请求号再发一次；金额 0、1.234、空、5000；服务员账号调用；不存在的账单。
- 预期：重放 200 不重复；非法金额 400 `invalid_amounts`；服务员被拒；未知账单 404。

**场景 3：× 删除**
- 操作：删 €0.20 行；再删同一行。
- 预期：第一次成功、不要求填原因；第二次 404；操作记录有 ITEM_QTY_DECREMENTED；刷新后总额 €44.20。

**场景 4：折扣 + 收款 + 打印发票**
- 操作：整单折扣 10%，收款 €39.78，打印发票。
- 预期：折扣按含 Take away 的总额算；最后一笔收款自动关台；发票里 2 行 `TAKEAWAY`（0.10、0.30）各自一行、13%、`open_price`。

**场景 5：改税率**
- 操作：老板把 Take away 税率改为 23 → 重新开发票；输入 101、6.5；服务员修改；改回 13。
- 预期：发票 Take away 行变 23.00；非法值 400；服务员 403。

**场景 6：按菜结账分 Take away**
- 前置：VIP888 开台，加 5 / 3.5 / 2 三笔。
- 操作：Ana 拿 5 + 2 的一半，Bruno 拿 3.5 + 2 的一半；先收 Ana €6.00；再尝试删 Ana 的 5、共享的 2；往待分池加 1.5 再删。
- 预期：Ana €6.00、Bruno €4.50；已付 / 半付的行删不掉（409 `claimed_by_ticket`，界面提示「已分给客人，请先在分单里退回」）；池里的 1.5 可删。

**场景 7：不当作菜品**
- 操作：查当日菜品、厨房看板；只有自助 + Take away 的订单状态。
- 预期：都不出现 Take away；订单状态 done（不卡厨房）。

**场景 8：隔离回归（原有分单结账）**
- 操作：取本地库最近 60 张真实账单（按菜 35、均分 7、整桌 18，均不含 Take away），分别用 main 和本分支代码生成发票明细、整桌小票、按人小票、结账页菜品行、总额、订单状态、菜品 id 列表。
- 预期：两边输出逐字节相同。

**场景 9：界面**
- 操作：老板账号打开 A-20 结账页（窄屏面板），加 5,5 和 2.3（逗号小数），点 × 删除 5.50；打开功能设置页。
- 预期：按钮在汇总栏；「再加一项」自动聚焦新行；窄屏名称独占一行不被压缩；总额 €43.70 → €38.20；设置页显示 13%。

## 5. 风险与待确认

1. **原有问题（非本次引入，已在 main 证实）**：按菜结账「给某个人单独开发票」时，只要分单数据带 `party_id`，`buildBillSyncJobPayload` 就返回 `empty_lines`（`consumersForLineFromPersons` 返回的份额不带 party_id，按人匹配永远对不上）。本地 60 张真实账单里 27 张如此，main 与分支一致。按「不影响原有分单」的要求本次未改，建议单独处理。
2. **Agent 版本**：店里 Agent 升级到含 `open_price` 的版本前，同一张发票里有 2 笔以上**不同金额**的 Take away 会被旧 Agent 以 `item_code_conflict` 拒绝；只有 1 笔、或金额相同时旧 Agent 照常开。需发 Agent 新版本。
3. 探索测试中观察到：Ana 付款后，只分给未付款 Bruno 的那行也被拦（409），需先在分单里退回再删；最终重跑未单独覆盖这一条，按【未验证】看待。
4. Take away 税率为全店一个值；若同店需要不同税率的打包，需要再议。
