## 2. 核心业务规则

1. 【本次新增】送厨状态只有一处：`resolveSushiSendGuidance`，只看**整桌本轮**（未送厨 / 倒计时 / 送厨失败 / 已送厨冷却），**不看**本机购物车 —— 购物车里有菜时，本桌未送厨的提醒不能消失。
2. 【本次新增】引导条与核单顶部是同一条提示（同一组件、同一文案函数），不会两处说法不一。
3. 【已实现，本次保持】送厨唯一入口仍在核单；底栏「去送厨 · N 道」只打开核单，不直接送厨，也不跳过确认弹窗。
4. 【本次新增】N 道 = 整桌未送厨免费菜份数；托盘角标 = 本机本轮份数（两者不混用）。只有同桌有未送厨菜时，本机也显示「去送厨」（任何人都能送）。
5. 【已实现，本次保持】收费菜即时下单、不进轮次、不占份数。【本次新增】核单里只读显示本轮开始后整桌已直接送厨的收费菜（✓数量），不可改、不计入 N 道、不参与送厨，本轮送出后随核单清空。
6. 【本次新增】顶栏只显示份数：有未送厨份数「本轮 x/M」，否则（含已送厨冷却中）「每轮最多 M」。
7. 【已实现，本次保持】冷却期服务端拒绝写入轮次行（409 `round_cooldown_active`），前端加免费菜提示「送厨冷却中，请稍候」。
8. 【本次新增】经典店不传引导条，底栏、底距、toast 位置与改动前一致（引导条高度变量为 0）。
