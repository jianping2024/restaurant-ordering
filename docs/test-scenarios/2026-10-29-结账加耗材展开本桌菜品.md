# 本次改动业务场景测试报告 — 结账加耗材后展开本桌菜品

## 1. 本次修改

- **内容：** 结账详情「本桌菜品」在进页并完成列表灌入后，可删供给行（外卖耗材 / 堂食打包费）数量变多时自动展开。
- **文件：** `CheckoutTableItemsSection.tsx`、`checkout-session-lines.ts`（`countCheckoutSupplyChargeLines`）、`checkout-session-lines-supply-count.test.ts`、本场景文档
- **角色 / 页面：** 收银结账台详情
- **唯一写法：** 供给行计数 sole `countCheckoutSupplyChargeLines`；折叠状态仅 `CheckoutTableItemsSection` 内部 `open`；空列表不记基准，避免进页灌数据误展开

## 2. 核心业务规则

1. 【本次新增】进页后供给行数增加 → 自动展开「本桌菜品」。
2. 【本次新增】进页时账单里已有耗材：不因首屏灌数强制展开（保持默认收起）。
3. 【已实现】收银仍可手动点标题折叠/展开。
4. 【已实现】删供给行不因此收起。

## 3. 详细测试场景

### 场景 1：外卖加耗材后自动展开

- **前置状态：** A-20 外卖结账单；「本桌菜品」收起（▸）。
- **操作过程：** 「＋ Embalagem」→ 给「Caixa pequena」加数量 →「Adicionar a conta」。
- **预期结果：** 「本桌菜品」展开（▾），可见餐盒（小）。
- **标签：** 【已验证】

### 场景 2：进页已有耗材 — 不强制展开

- **前置状态：** 账单已有耗材；新进详情。
- **预期结果：** 默认收起（▸）。
- **标签：** 【已验证】

### 场景 3：堂食加打包费（同规则）

- **说明：** 与耗材共用 `chargeLineId` 计数与同一展开 effect；本轮未单独开堂食桌点打包费 UI。
- **标签：** 【未验证】（逻辑同场景 1；单测已覆盖 takeaway: 行计入）

### 场景 4：计数单测

- **标签：** 【已验证】
