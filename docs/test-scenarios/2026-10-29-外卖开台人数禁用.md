# 本次改动业务场景测试报告：外卖开台人数禁用

## 1. 本次修改

- **内容：** 外卖桌开台/桌台详情仍显示自助人数区，但加减禁用；开台走 `open-takeaway`；`POST …/buffet` 对外卖桌/外卖会话拒绝。看板分组补查 `is_takeaway`，会话元数据带 `orderingChannel`。
- **文件：** `WaiterBoardOpenTableSheet/Form`、`WaiterTableDetail*`、`WaiterBuffetPackagesEditor`、`staff-board`、`buffet-waiter-pipeline`、`buildTakeawayTableIdSet`、`postWaiterOpenTakeawayClient` 等。
- **角色 / 页面：** 前台楼面看板（开台弹窗、桌台详情）、外卖加菜 API、关台。
- **UAT 基址：** `http://localhost:3002`（feature 分支，非 :3000）

## 2. 核心业务规则

1. 【本次新增】外卖桌：人数控件可见但不可改，人数为 0；不写自助人头费。
2. 【已实现】开台记下 `ordering_channel=takeaway`；之后只认会话渠道。
3. 【本次新增】`POST …/buffet`（open/save）在外卖桌或外卖会话 → `buffet_not_allowed_on_takeaway_session`。
4. 堂食开台人数加减仍可用。

## 3. 详细测试场景

### 场景 1：开台弹窗 — 人数禁用 + 说明

- **前置：** A-20 在外卖组、空闲；前台已登录。
- **操作：** 看板外卖组点 A-20「Abrir」。
- **预期：** 弹窗仍有 Buffet 成人/儿童；四个步进器 `disabled`；有外卖说明文案；无「预计合计」；主按钮「Abrir mesa」。
- **标签：** 【已验证】Chrome DevTools 打开 `localhost:3002`，a11y 四钮 disabled；截图留存。

### 场景 2：UI 开台后会话无自助行

- **前置：** 场景 1 弹窗。
- **操作：** 点「Abrir mesa」。
- **预期：** 会话 `ordering_channel=takeaway`；订单数 0；无 `buffet_base` 行。
- **标签：** 【已验证】SQL：`065da30c-…` takeaway，`buffet_lines=0`。

### 场景 3：桌台详情 — 已开外卖台人数仍禁用

- **前置：** API/UI 已开外卖会话。
- **操作：** 打开桌台详情。
- **预期：** 成人/儿童为 0 且 disabled；说明文案在。
- **标签：** 【已验证】`evaluate_script` 四钮 `disabled:true`。

### 场景 4：改人数接口拒绝（save）

- **前置：** 外卖会话 open。
- **操作：** `POST …/buffet` intent=save，adult_count=1。
- **预期：** 409 `buffet_not_allowed_on_takeaway_session`。
- **标签：** 【已验证】`mesa-local-uat` expect-status 409。

### 场景 5：空闲外卖桌冷开 buffet 拒绝（open）

- **前置：** A-20 空闲。
- **操作：** `POST …/buffet` intent=open。
- **预期：** 409 同上（不得写成堂食自助台）。
- **标签：** 【已验证】

### 场景 6：外卖加菜按外卖价

- **前置：** 外卖会话。
- **操作：** `POST …/orders/append` 茉莉花茶 qty=1。
- **预期：** 200；行价 €9.90；无自助基价。
- **标签：** 【已验证】

### 场景 7：关台清理

- **操作：** `close-table-session` confirm_close + reason other。
- **预期：** 200 关台成功。
- **标签：** 【已验证】（两次：加菜后关、UI 开台后关）

### 场景 8：堂食开台回归 — 人数可改

- **前置：** VIP1 空闲桌 A-04。
- **操作：** 点 Abrir 开台弹窗。
- **预期：** 成人/儿童步进器 `disabled:false`；无外卖说明。
- **标签：** 【已验证】未真正确认开台（只验控件）。
