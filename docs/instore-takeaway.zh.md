## 0. 一句话与边界

**店内外卖** = 店主建一个「外卖组」，组内桌台扫码或员工代点时只看到「可外卖」菜品、按外卖价下单；出单、结账、开票、关台与堂食完全相同；外卖结账时员工可手动加「外卖耗材」商品（餐盒/杯等，可不加）；开台时记下「这桌是外卖」，重打小票与营收拆分都认这笔记录。

| 名称 | 含义 | 与本需求关系 |
|------|------|--------------|
| 店内外卖 | 本文档的新功能 | — |
| 现有「打包费」TAKEAWAY（`OrderItemKind 'takeaway'`，`takeaway_vat_rate`，收银员手填单价） | **堂食**没吃完打包带走的费用 | **保持不变**；外卖会话结账界面隐藏该按钮，接口也拒绝 |
| 外卖耗材（新） | 餐盒、杯子等；商品「销售方式」选「外卖耗材」，**不**占用特殊菜品类别 | 仅外卖会话结账时可加；单价 = 该商品自己的价格；**可不加，不拦结账** |

### 0.1 堂食隔离与开关下架（硬保证）

1. **默认关**：总开关默认关闭；未开启前，堂食开台 / 点餐 / 结账 / 打包费 / 转台并台 / 同行组与上线本功能前**同一行为**（不因仓库里有外卖字段而改变堂食路径）。
2. **开启后堂食照旧**：未划入外卖组的桌、渠道为堂食的会话——菜单仍是原堂食菜单与堂食价；不强制可外卖；结账仍是原「＋ Take away」打包费；不出现「加外卖耗材」。外卖逻辑**不得**改写堂食会话的加单定价与可见菜规则。
3. **随时下架**：店主可关总开关下架外卖能力。若外卖组仍有未结账桌（`open` / `billing`）→ 先结清或关台，否则关不了（避免进行中的外卖单被改口径）。关成后：不再开出新的外卖会话；原外卖组桌按堂食开台与点餐；楼面不再置顶外卖区；营收页不再显示堂食/外卖分段。配置（外卖组标记、销售方式、外卖价）保留不删，再开即恢复。
4. **关开关后仍藏着的唯一菜单例外**：销售方式仍是「外卖耗材」的商品**继续不进任何点餐菜单**（含堂食）。总开关关闭时销售方式编辑入口一并隐藏，故若要把耗材收回普通菜：须**先再打开总开关**，把销售方式改回「仅堂食」或「可外卖」，然后再关（或不关）。其它「可外卖」菜在关开关后按堂食价、进堂食菜单，与普通菜一样（不必先开开关）。

## 1. 全链路总览

```
① 总开关「店内外卖」开启（默认关；关 = 下架外卖，堂食路径见 §0.1）
   │
   ├─② 桌位分组：用外卖图标标成「外卖组」（全店唯一）
   │      └─ 组内桌台 = 外卖桌（楼面看板中外卖组固定排最左）
   │
   └─③ 商品「销售方式」三选一：仅堂食 / 可外卖（+ 外卖价，必填 > 0）/ 外卖耗材
          └─ 外卖耗材：餐盒/杯等，可多件，挂普通类别下；期间不进点餐菜单，改回后立刻重新出现

④ 员工在楼面看板外卖组点空闲桌 → 现有开台面板（隐藏人数/套餐，只剩〔开台〕）
   └─ 开台时记下「外卖」身份（会话上保留）
   └─ 开台小票开关开 → 打印外卖开台小票（含扫码点餐二维码）

⑤ 点单：员工代点 或 客人扫码（普通点餐页）
   └─ 只显示可外卖菜品 · 外卖价 · 服务端同一规则校验与定价
   └─ 堂食桌 / 堂食会话：不受上列过滤影响（§0.1）

⑥ 出单：档口小票 / 厨房屏照常，标「外卖」（认开台记下的身份；重打仍标）

⑦ 结账：与堂食相同（含分单）
   └─ 员工可手动加外卖耗材（选商品 + 数量）；不加也能结账

⑧ 收款 · 开票 · 关台：与堂食相同
   └─ 营收：今日卡 / 区间营业额 / 日统计 / 增值分析均可按堂食·外卖筛或对比（认开台身份）
   └─ 总开关关闭 → 上述界面不显示外卖/渠道拆分，只显示合计
```

## 2. 总开关「店内外卖」

| 项 | 规则 |
|----|------|
| 位置 | 功能开关页，唯一编辑入口 `FeatureFlagsManager`；flag 键 `takeaway_ordering`，**默认关** |
| 权限 | `settings.features.manage` |
| 开启后解锁 | 分组编辑弹窗的外卖标记、菜品表单「销售方式」 |
| 开关说明文案 | 「开启后可设外卖组、可外卖菜品和外卖耗材。」（不写实现细节） |
| 关闭前检查 | 外卖组有未结账桌台（会话 `open` / `billing`）→ **不允许关闭**，提示：「外卖组还有未结账的桌台」 |
| 关闭二次确认 | 标题「关闭店内外卖？」，正文「外卖组的桌台将变回堂食桌。」，按钮〔取消〕〔确认关闭〕（危险色） |
| 关闭后（下架） | 见 §0.1：外卖组**按普通分组用**（组名、组员、标记保留；外卖图标编辑入口隐藏；看板不再固定最左、按原 `sort_order`）；**新开台**一律堂食（选人数/套餐、堂食菜单与堂食价）；营收隐藏渠道分段。销售方式 / 外卖价 / 外卖组标记**不删**；「外卖耗材」商品仍不进点餐菜单。已关台历史外卖会话：重打仍标外卖，库内营收渠道不变。重新开启即恢复外卖能力 |
| 堂食路径 | 开关开或关，渠道为堂食的会话加单/结账**不得**走外卖价或可外卖过滤；实施时堂食分支与外卖分支分开判断（§11.2），禁止改堂食默认逻辑去「兼备用外卖」 |

## 3. 外卖组（桌位分组）

| 项 | 规则 |
|----|------|
| 设置位置 | 桌位管理 → 分组管理 → 分组**新增/编辑弹窗**内一个外卖图标开关 +一句说明「组内桌台按外卖价点单；开台可见人数但不可改」；总开关关闭时不显示 |
| 列表展示 | 分组列表**只在外卖组那一行**显示外卖图标；其它分组行不显示「可标记 / 不可标记」状态 |
| 唯一性 | 全店最多一个外卖组（DB 部分唯一索引保证）；已有外卖组时，其它分组编辑弹窗里的开关置灰，并写明「已有外卖组：{组名}」 |
| 外卖桌 | 外卖组内的桌台；与普通桌一样有桌号、二维码；QR 卡片/打印显示分组名 |
| 楼面看板 | 总开关开启时，外卖组分区固定排在分组行**最左**，不受分组 `sort_order` 影响，分区标题带外卖图标；入口即此分区，不另加按钮；分区内桌台卡片与堂食卡片**同一格式**（「用餐中 / 空闲」等），不再逐张写「外卖」 |
| 总开关关闭时 | 变回普通分组（见 §2），标记保留，重新开启自动恢复 |
| 变更锁 | 组内任一桌台有未结账会话（`open` / `billing`）时，**不允许**：增删组员、取消外卖组标记、删除外卖组 |
| 转台 / 并台 | **仅外卖组内的桌 ↔ 外卖组内的桌**允许；外卖桌 ↔ 堂食桌**禁止**（界面不提供目标 + 接口拒绝） |
| 同行组 | 外卖桌**不能**加入同行组（界面不提供 + 接口拒绝） |

## 4. 商品「销售方式」

一个单选取代两个互斥开关：**仅堂食 / 可外卖 / 外卖耗材**（数据为一个枚举列，见 §11.1；不存在「两个都开」的状态）。

| 项 | 规则 |
|----|------|
| 表单 | 价格下方一组三选一「销售方式」；默认「仅堂食」；总开关关闭时整组隐藏且不校验，值保留（要把「外卖耗材」改回普通菜，须先开总开关，见 §0.1.4） |
| 可外卖 | 选中后显示「外卖价」，**必填且 > 0**；税率 = 该菜 `vat_rate`（与堂食一致） |
| 菜品列表 | 可外卖：信息行（meta）显示「外卖 €x」；外卖耗材：信息行显示「外卖耗材」；标题仍为 `formatMenuCatalogItemLabel` |
| 价格快照 | 已下单的行保持下单时价格；改外卖价只影响之后的新单 |

## 5. 外卖耗材

不设「打包类」类别。餐盒、杯子等就是普通商品，「销售方式」选「外卖耗材」。

| 项 | 规则 |
|----|------|
| 数量 / 归类 | 全店可有多件耗材商品；挂在任意普通类别下方便后台管理 |
| 新建流程 | 与现有新建菜品相同 |
| 表单（选外卖耗材时） | **只隐藏不清空**：外卖价、时段、档口、口味、过敏原不显示、不校验；库里旧值保留但不生效（耗材行是独立行类型，菜单 / 厨房 / 出单都不读这些字段）；**商品编码必填**（开票用）；价格 = 该商品自己的定价 |
| 推荐中的商品 | 商品在推荐栏里时**不允许**选「外卖耗材」，保存提示「请先移出推荐」（不替店主删推荐） |
| 改回其它销售方式 | 立刻重新出现在点餐菜单（按所属类别、上下架等原规则）；之前隐藏的时段、档口等配置原样生效 |
| 菜单可见性 | 外卖耗材不出现在任何点餐菜单（客人扫码、员工代点、堂食、外卖）；点餐加单接口也拒绝 |
| 使用场景 | 仅外卖会话结账时可选添加（§8）；**不加也能结账**；店内尚无耗材商品时，结账不显示「＋ 外卖耗材」 |

## 6. 外卖桌开单与点单

### 6.1 开单

| 项 | 规则 |
|----|------|
| 谁开 | 员工在楼面看板外卖组分区点空闲桌台；客人**不能**自行开台（与堂食一致） |
| 开台入口 | **复用现有开台面板**（`WaiterBoardOpenTableSheet`）：外卖桌仍显示人数/套餐区，但加减**禁用**（人数为 0），说明「不按人数收费」；〔开台〕走 `open-takeaway`；不新增「点桌直接开台」路径（避免误触留空单）。开台后桌台详情同样显示但禁用，且 `POST …/buffet` 拒绝外卖会话 |
| 开单内容 | 无人数写入、无自助套餐、无自助基价、无人头费 |
| 开台记下身份 | 开台成功时在会话上记下「外卖」；之后改分组、关总开关、关台，都不改这笔记录 |
| 开台小票 | 遵循现有开关 `open_table_receipt_print`：开 → 打印外卖开台小票，内容含桌名、时间、**该桌扫码点餐二维码**；关 → 不打印 |
| 堂食开台小票 | **保持现状**（档口单格式、一行合计，无二维码） |

### 6.2 点单

| 项 | 规则 |
|----|------|
| 入口 | 员工代点（楼面桌台详情 → 点餐页 `from=waiter`）或客人扫外卖桌二维码 |
| 页面 | 一律**普通点餐页**；寿司店的外卖桌也不用 `SushiMenuPage`（无轮次界面）；轮次点餐接口对外卖桌拒绝 |
| 点单模式 | 一律单点：无自助基价、无轮次、`per_person_qty_limit` / `over_limit_unit_price` 不生效 |
| 可见菜品 | 只显示「可外卖」菜品（外卖耗材本来就不在菜单里）；推荐栏同样过滤；过滤后为空的分类隐藏；菜品时段规则照常生效 |
| 显示价格 | 外卖价 |
| 页面标识 | 页头桌名旁一个「外卖」标签，让客人知道是外卖价；其余界面不新增 |
| 服务端校验 | 加单按会话渠道（§11.2）判定菜单与定价；非可外卖菜品 → 拒绝（`menu_item_not_takeaway`）；外卖耗材 → 拒绝；单价取外卖价，不信任客户端价格 |
| 购物车失效 | 购物车里的菜在下单前被关掉「可外卖」→ 下单被拒，点餐页提示并移出该菜 |
| 扫码限制 | 地理围栏等现有扫码规则照常 |

## 7. 出单

| 项 | 规则 |
|----|------|
| 档口小票 | 照常按档口出单；桌名为外卖桌 `display_name`；**单头标「外卖」**（认会话开台记下的身份） |
| 厨房屏 | 照常显示；桌名旁「外卖」标签（同上） |
| 重打 | 重打出品单 / 开台小票时**继续标「外卖」**，不因后来改分组或关总开关而变成堂食 |
| 外卖耗材 | 不进档口小票、不进厨房屏（账单行内部类型见 §11.2；界面不出现 packaging 字样） |

## 8. 结账

| 项 | 规则 |
|----|------|
| 流程 | 与堂食完全相同：整桌、AA、按菜分单（各付各）均可用 |
| 是否外卖会话 | 与点单相同：只看会话上开台记下的渠道（§11.2），不看这桌现在还在不在外卖组 |
| 加外卖耗材 | 外卖会话且店内已有外卖耗材商品时，结账底栏原「＋ Take away」**同一位置**换成「＋ 外卖耗材」：弹窗列出全部耗材商品，每行步进器填数量；只提交数量 ≥ 1 的行，全部为 0 时「加入账单」禁用，**员工手动**添加；交互参考现有打包费弹窗；单价 = 商品自身价格 |
| 可不加 | **不强制**；不加也不拦截账、收款、关台 |
| 耗材行 | 单独成行、可改可删（复用现有打包费的写入、防重、作废链路）；名称 / 编码 / 税率 / 单价取该商品自身；开票单独成行 |
| 原打包费按钮 | 外卖会话结账界面**隐藏**；堂食会话不变；外卖会话调用原打包费接口 → **拒绝**；堂食会话调用加外卖耗材接口 → **拒绝** |
| 分单中的耗材行 | 与现有打包费行规则一致（实施时核实代码后写明） |
| 权限 | 加外卖耗材 = 现有加打包费同一权限 |
| 收款 / 开票 / 关台 | 与堂食相同 |

## 9. 营收按堂食 / 外卖拆分

开台记下的「外卖 / 堂食」身份是唯一口径：关台落账、收款进日统计、首页今日营业额、区间营业额、增值分析都认它；后来改分组或关总开关**不改写**已开台会话的渠道。

| 项 | 规则 |
|----|------|
| 今日营业额卡 | 总开关**开启**时：保留现有「已收 + 未收」大数字；其上增加分段 **全部 / 堂食 / 外卖**。选「全部」时大数字为合计，其下多一行小字「堂食 €x · 外卖 €y」做对比（**只拆已收**：两项之和 = 已收大数字）；选「堂食」或「外卖」时大数字只显示该渠道。旁侧「今日桌数 / 用餐人数」「当前用餐桌数 / 人数」卡**不随该分段变化**（与现在一样显示全店合计）。示意稿：[`instore-takeaway-ui-mock.html`](./design/instore-takeaway-ui-mock.html) 第 10 屏 |
| 区间营业额 | 总开关**开启**时：同一套分段 + 选「全部」时的对比行 |
| 日统计 / 关台落账 | 写入时带上开台渠道，历史日数字不因后来改配置而变；上线前的历史会话与日统计一律补为「堂食」 |
| 增值分析 | 总开关**开启**时：同一「全部 / 堂食 / 外卖」分段筛指标；不另起第二套渠道控件 |
| 总开关**关闭**时的界面 | **不显示**分段与「堂食·外卖」对比行；页面只呈现与现在一样的合计。库里渠道历史仍保留；重新开启后再显示 |

## 10. 变更约束汇总

| 操作 | 条件 | 结果 |
|------|------|------|
| 关闭总开关（下架） | 外卖组有未结账桌台（`open` / `billing`） | 拒绝 + 提示 |
| 关闭总开关（下架） | 无未结账外卖桌 | 二次确认后关闭；之后堂食路径见 §0.1 |
| 外卖组增删组员 / 取消标记 / 删除 | 组内有未结账会话（`open` / `billing`） | 拒绝 |
| 设第二个外卖组 | 已有外卖组 | 拒绝（置灰） |
| 商品选「外卖耗材」 | 商品在推荐栏里 | 拒绝，提示「请先移出推荐」 |
| 商品选「外卖耗材」 | 其它情况 | 允许；时段/档口等只隐藏不清空 |
| 外卖耗材改回其它销售方式 | 任意（无未结账约束） | 允许；立刻回点餐菜单，原配置生效 |
| 外卖桌 ↔ 堂食桌 转台、并台 | 任意 | 拒绝 |
| 外卖组内桌 ↔ 外卖组内桌 转台、并台 | 两侧都是外卖组内桌 | 允许 |
| 外卖桌加入同行组 | 任意 | 拒绝 |
| 外卖会话加原打包费 / 堂食会话加外卖耗材 / 点餐加外卖耗材 / 外卖桌走轮次点餐 | 任意 | 接口拒绝 |

## 11. 数据与判定（实施草案）

### 11.1 字段

| 表 | 新增 | 说明 |
|----|------|------|
| `restaurants.feature_flags` | `takeaway_ordering` | 总开关 |

### 11.2 唯一判定点

| 判定 | 唯一来源 |
|------|----------|
| 桌台的点单渠道（菜单、外卖价、出单标记、重打、营收） | 唯一函数（如 `resolveTableOrderingChannel`）：**有会话 → 会话渠道字段**；无会话 → 仅当总开关开 **且** 桌在外卖组才为外卖，否则堂食。总开关关 → 无会话浏览与新开台均为堂食（即使桌仍挂在曾标过的外卖组）。开台写入渠道也调用它。客户端、服务端、打印、统计不另写第二份判断 |
| 外卖菜单可见 + 价格 | **仅渠道 = 外卖时**启用可外卖过滤与外卖价；渠道 = 堂食时走原堂食菜单与堂食价（与未上线本功能相同）。客户端 `resolveCustomerMenuCatalogView` 与服务端 `resolveAppendCartItems` 共用同一函数，按渠道参数分支，禁止改堂食默认分支 |
| 总开关与下架 | `takeaway_ordering = false` 时：不得开出渠道 = 外卖的新会话；编辑入口隐藏；营收 UI 不拆渠道。不删除配置行 |
| 外卖耗材不进菜单 | 同一 catalog view 排除 `takeaway_role = 'packaging'` 的商品；`resolveAppendCartItems` 同样拒绝 |
| 耗材行不算菜 | 账单行内部类型 `OrderItemKind 'packaging'`（**仅代码名**；界面文案一律「外卖耗材」，不展示 packaging）；`isMenuCatalogItem` 排除 → 厨房屏、楼面待出餐、菜品历史、排行、点评、寿司限量一次性排除，且不依赖档口配置 |
| 客人可点单门槛 | 与现行一致：会话 `open` 即可加单（外卖开台不写自助餐行） |
