## 1. 本次修改

- **内容**：分组管理改成稠密列表（一眼看全组桌号、列表不显示备注）；去掉「调整顺序」独立弹窗；组内桌序并进编辑弹窗（已选可拖 + 下方勾选）；保存时同一请求写入归属与桌序。
- **文件**：`TableGroupsManager.tsx`、删除 `TableGroupMemberOrderModal.tsx`、`dashboard-table-groups-server.ts` / client、`restaurant-table-groups.ts`(+test)、i18n、设计稿、本报告。
- **角色 / 页面**：后台管理员 · `/dashboard/tables?tab=groups`
- **唯一写法自检：**
  - 列表桌号预览只走 `formatGroupMemberTablePreview`（全量 chip，无 `+N`）。
  - 组内顺序只在编辑里拖 `form.tableIds`，保存走 create/update → `applyMemberTableOrderAdmin`；UI 不再调用 `reorder_members`。
  - 备注只在编辑表单出现，列表无备注行。

## 2. 核心业务规则

1. 打开分组管理即可看到每组全部桌号（多时可在 chip 区滚动）。
2. 列表不展示备注；备注仅编辑可见可改。
3. 行上只有「编辑 / 删除」；无「调整顺序」。
4. 组间顺序：拖行左侧手柄，立刻写库（与改前一致）。
5. 组内顺序 + 归属：编辑里拖已选列表 / 勾选池，点保存一次写入；组内顺序写入 `restaurant_tables.sort_order`。
6. 删除分组：桌位保留且变为未分组。

## 3. 详细测试场景

### 场景 1：列表一眼看全桌号且无备注

- **前置状态**：店主登录；店内已有分组且某组桌数 > 6、某组有备注
- **操作过程**：打开 `/dashboard/tables?tab=groups`
- **预期结果**：该组 chip 显示全部桌号（无 `+N`）；列表看不到备注灰字；行上无「调整顺序」
- **数据验证**：界面 chip 数 = 该组成员数
- **异常恢复**：刷新后仍全量显示

### 场景 2：编辑里改组内顺序并保存

- **前置状态**：场景 1；选一组 ≥2 张桌
- **操作过程**：点编辑 → 在「本组桌位」拖动顺序 → 保存 → 回到列表看 chip 顺序
- **预期结果**：列表 chip 顺序与保存后一致；楼面看板同组桌卡相对顺序随之变化（若本测打开看板）
- **数据验证**：PATCH 更新成功；组成员 `table_ids` 顺序对应的 `sort_order` 已重排
- **异常恢复**：取消编辑不写入；再打开编辑仍是旧序

### 场景 3：编辑里勾选移入 / 移出桌位

- **前置状态**：有未分组或其它组桌位
- **操作过程**：编辑 A 组 → 勾选一张他组/未分组桌 → 保存；再编辑去掉一张桌 → 保存
- **预期结果**：桌位归属正确；列表 chip 同步；他组不再含移出桌（一对一归属）
- **数据验证**：`restaurant_table_group_members` 仅一侧有该桌
- **异常恢复**：保存失败时弹窗仍开、列表未变

### 场景 4：拖分组顺序

- **前置状态**：≥2 个分组
- **操作过程**：拖左侧手柄对调两组 → 松手
- **预期结果**：列表顺序立刻变；刷新后保持
- **数据验证**：分组 `sort_order` 更新
- **异常恢复**：失败时回滚列表顺序（既有行为）

### 场景 5：备注只在编辑

- **前置状态**：某组备注非空
- **操作过程**：列表确认无备注行 → 编辑看到备注 → 可改保存
- **预期结果**：列表仍不显示备注；再进编辑可见新备注
- **数据验证**：库中 `remarks` 已更新

### 场景 6：回归 — 删除分组

- **前置状态**：可删的空测分组或确认可删的组
- **操作过程**：删除 → 确认
- **预期结果**：组消失；原桌位仍在桌位配置且未分组
- **数据验证**：无该 `group_id` 成员行

### 场景 7：回归 — 桌位配置页仍可用

- **前置状态**：同店
- **操作过程**：切到「桌位配置」子 tab
- **预期结果**：桌位列表/二维码区正常，无黑屏
