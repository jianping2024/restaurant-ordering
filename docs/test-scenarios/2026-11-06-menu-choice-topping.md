# 口味分组 + 浇头（点单配置）业务场景

## 本次修改

- 库表：`menu_choice_groups` / `menu_choice_options`；菜品 `choice_bindings`、`topping_binding`
- 后台：菜单「口味分组」Tab；菜品编辑勾选口味与浇头（先选一个类别）
- 顾客：挂了配置的菜列表加号进详情；必选未完成不能加入；购物袋按配置分行；下单展开浇头为独立行，口味进主菜备注

## 核心业务规则

1. 口味 ≠ 风味提示 ≠ 预选备注
2. 每组口味单选必选一；浇头可按 `required` 必选至少一种
3. 未挂配置：列表可直接加减
4. 购物袋：主菜 + 口味 + 浇头 + 备注全相同才叠份
5. 下单：主菜一行（备注含口味文案）+ 浇头各成行（数量 × 主菜份数）

## 详细测试场景

### 场景 1：后台建口味并挂到菜

- **前置**：店员已登录菜单页
- **操作**：口味分组 Tab 新建组与口味 → 菜品编辑勾选 → 保存
- **预期**：保存成功；顾客目录该菜 `choice_bindings` 非空
- **数据验证**：`menu_choice_*` 有行；菜品 jsonb 含对应 group/option id

### 场景 2：未配置菜仍可列表加减

- **前置**：某菜无 choice/topping
- **操作**：顾客菜单列表直接 +
- **预期**：进购物袋，不必开详情选口味

### 场景 3：已配置菜必须选完再加入

- **前置**：菜挂了至少一组口味
- **操作**：列表 + → 详情不选口味点加入
- **预期**：提示未选完；购物袋无新行
- **再操作**：每组选一项后加入
- **预期**：购物袋出现该行

### 场景 4：浇头必选 / 可选

- **前置**：浇头 `required=true` / `false` 各一菜
- **操作**：必选不选浇头加入 → 拒绝；可选不选浇头 → 可加入

### 场景 5：不同配置分行；相同叠份

- **操作**：同一主菜选不同口味各加 1；再重复相同配置加 1
- **预期**：不同口味两行；相同配置 qty=2

### 场景 6：下单展开

- **前置**：购物袋有主菜 + 浇头×2、主菜 qty=2
- **操作**：提交下单
- **预期**：订单主菜 2 份（备注含口味）；浇头菜单行 qty=4；无重复主菜配置丢失

### 场景 7：回归

- 无配置菜列表加减、预选备注、风味提示展示仍正常
- 寿司轮次菜单未因 `lineId` 购物车改动而无法加减（无配置路径）
