# 本次改动业务场景测试报告 · 套餐最少人数 + 价目成人/儿童开关

分支 `claude/buffet-min-guest-side-toggle-b7a662`。方案：`docs/buffet-min-guest-and-side-toggle.zh.md`。  
UAT 基址：`http://localhost:3005`（`MESA_NEXT_DIST_DIR=.next-uat`），本地 Docker Supabase，店铺白云 `restaurant-mohnrib5`，套餐「Buffet livre」，当前命中规则 = 晚餐 · 周末。

## 1. 本次修改

- 套餐新增「最少人数」`buffets.min_guest_count`（0–99，默认 0；成人+儿童合计）。
- 价格规则新增「收成人 / 收儿童」`buffet_price_rules.adult_enabled / child_enabled`（默认都开，至少一个；DB CHECK）。
- `resolve_buffet_prices` 随价格返回两个开关；楼面开台抽屉 / 详情 / 结账改人数按开关隐藏计数器、只显示开着那一侧的单价，并显示「本套餐最少 N 人」。
- 开台、已开台改人数、结账改人数：合计 < 最少人数或关掉的一侧 > 0 → 本地先拦 + 同源提示；服务端 409 `buffet_min_guest_count` / `buffet_side_disabled`。
- 冷开台的取价 + 可开台 + 人数校验都在建会话之前：被拒的开台不再留下空会话。
- 后台：套餐行「最少人数」输入；规则弹窗两个勾选（不勾 → 价格框禁用、保留原值）；规则价格列表 / 矩阵 / 试算只显示开着的一侧。

## 2. 核心业务规则

1. 合计（成人+儿童）< 最少人数 → 开台、改人数、结账改人数一律拒绝，提示「本套餐最少 N 人，当前 M 人」。
2. 规则关掉的一侧人数必须为 0，接口也拒绝；关掉的一侧在楼面与后台都不显示价格。
3. 最少人数 > 0 时人数减不到 0，「人数改为 0？」确认不会出现。
4. 改设置走现有保存接口，`buffet_config_version` +1，开台抽屉重新拿到最少人数和开关；旧 v2 缓存因 key 变为 v3 自动作废。
5. 合并同套餐两桌照常（价格列仍 NOT NULL）。
