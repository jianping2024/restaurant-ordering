## 1. 本次修改

- **内容**：收银结账详情的粘性摘要条，在金额上面显示与队列同一句桌号（`桌` + 该单 `display_name`）。窄屏「返回列表」仍在桌号上面。菜品行里的 `A4` 仍是自助餐人数。
- **文件**：`CheckoutRequestDetail.tsx`（`SettlementBar`）、`StaffCheckoutSplitEditor.tsx`、`docs/checkout-dashboard-ui.zh.md`、本报告。
- **角色 / 页面**：收银员 `/dashboard/checkout` 选中一桌之后的详情。楼面、后厨、历史账单未改。

## 2. 核心业务规则

1. 【本次新增】详情摘要条的桌号与队列卡片同一句：`checkout.table` + `bill_splits.display_name`。不使用桌台 id。
2. 【本次新增】这句桌号在摘要条里面，摘要条粘在员工顶栏下面。往下滚时桌号和金额一起留在顶栏下方。
3. 【已实现】窄屏选中一桌后队列隐藏；宽屏队列仍在左侧。
4. 【已实现】菜品行 `Buffet livre · A4` 是 4 位成人，不是桌号。

## 3. 详细测试场景

### 场景 1：手机上队列藏起后仍看见表号 【已验证】

- **前置状态**：前台已登录。队列有 A-01、A-19、A-02。视口宽 390。
- **操作过程**：打开结账请求，点「桌 A-19」。
- **预期结果**：队列卡片消失，只剩详情。金额上面是大字「桌 A-19」，上面还有「返回列表」。
- **数据验证**：`GET …/checkout/requests` 里 A-19 的 `display_name` 是 `A-19`。页面文字与之一致。
- **异常恢复**：未改数据。点返回列表可回到队列（本场景未点）。

### 场景 2：往下滚时桌号粘在顶栏下，且不跟菜品人数混 【已验证】

- **前置状态**：场景 1，已展开「本桌菜品」。视口高收到 520，页面向下滚了约 300px。
- **操作过程**：滚到能看见菜品和「取消」。
- **预期结果**：黑顶栏下仍是「返回列表」和「桌 A-19」，再下面是消费 / 应收 / 待收。菜品行是 `Buffet livre · A4`，桌号仍是 A-19。
- **数据验证**：测量摘要条 `position: sticky`、`top: 56px`。滚后桌号顶边仍在 88px，没有滚出屏幕。
- **异常恢复**：不涉及写入。

### 场景 3：宽屏左侧队列和右侧详情是同一句 【已验证】

- **前置状态**：同一登录，视口 1280 宽。当前选中 A-19。
- **操作过程**：看左侧卡片和右侧摘要。
- **预期结果**：两处都是「桌 A-19」。宽屏不显示「返回列表」。
- **数据验证**：两处可见文字都是 `桌 A-19`；返回按钮的容器 `display: none`。
- **异常恢复**：不涉及写入。

### 场景 4：换一桌，详情桌号跟着换 【已验证】

- **前置状态**：场景 3。
- **操作过程**：点左侧「桌 A-01」。
- **预期结果**：右侧变成「桌 A-01」。左侧三张卡片仍是 A-01、A-19、A-02。按菜分单区仍可看（Hong、剩余菜品）。
- **数据验证**：详情可见文字为 `桌 A-01`；队列三句桌号都还在。
- **异常恢复**：只切换查看，没有收款。

### 场景 5：桌名为空 【未验证】

- **前置状态**：当前队列三单都有桌名。
- **操作过程**：没有造一张空桌名的单。
- **预期结果**：与队列卡片相同，显示「桌」后面空白，不用桌台 id 填上。
- **数据验证**：无。
- **异常恢复**：不适用。
