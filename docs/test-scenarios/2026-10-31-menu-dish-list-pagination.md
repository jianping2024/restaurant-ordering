# 本次改动业务场景测试报告：菜单菜品列表翻页

日期：2026-10-31  
分支：`feat/menu-dish-list-pagination`  
UAT 基址：`http://localhost:3004`（feature worktree，非 `:3000`）

## 1. 本次修改

- **内容**：后台「菜单 → 菜品」列表按当前筛选结果做内存翻页；底栏唯一使用 `ListPaginationBar`（每页 10/20）；拖排序用页偏移换绝对下标；批量上下架/动图仍针对筛选全集。中文按钮文案由「本页全部上/下架」改为「筛选结果全部上/下架」。
- **文件**：`MenuManager.tsx`、`messages*.ts`、`docs/agent-sole-index.zh.md`、本场景文档。
- **角色 / 页面**：店主 · `/dashboard/menu?tab=items`（Washoku Sushi / luckytea）。
- **流程**：筛选/搜索 → 翻页 → 批量确认 count / 排序偏移语义。

## 2. 核心业务规则

1. 列表展示行 = `paginateList(visibleItems)`；脚唯一 `ListPaginationBar`。【本次新增】【已实现】
2. 每页档位仅 10 / 20。【本次新增】【已实现】
3. 换分类筛选、改搜索、改每页条数 → 回到第 1 页。【本次新增】【已实现】
4. 「筛选结果全部上架/下架」与提示 `{count}` = 当前筛选全集。【已实现】
5. 批量动图候选 = 筛选全集中符合条件的菜。【已实现】
6. 拖排序绝对下标 = `(page-1)*pageSize + 页内下标`。【本次新增】【已实现】
7. 顶栏「共 N 道」= 全店总数。【已实现】

## 3. 详细测试场景

### 场景 1：筛选结果多于一页时翻页

- **前置状态**：店主登录；REFRIGERANTE 筛选 20 道；每页 10。
- **操作过程**：打开菜品 tab → 见「Pagina 1 / 2 · 20 no total」→ 点下一页 → 见 0110…。
- **预期结果**：翻页条为统一图标控件；第 2 页内容变化。
- **数据验证**：顶栏仍 Total 207。
- **标签**：【已验证】pass

### 场景 2：改每页条数回第 1 页

- **前置状态**：停在第 2 页。
- **操作过程**：每页改为 20。
- **预期结果**：`Pagina 1 / 1 · 20 no total`；无下一页按钮。
- **标签**：【已验证】pass

### 场景 3：筛选结果全部下架确认 count（跨页语义）

- **前置状态**：REFRIGERANTE 20 道；每页 20（一页显示全）。
- **操作过程**：点「Ocultar lista filtrada」→ 见「Isto afeta 20 prato(s)」→ 取消。
- **预期结果**：确认框 count=20=筛选全集；取消无写入。
- **标签**：【已验证】pass（未实际下架，避免脏数据）

### 场景 4：分页下排序用绝对下标（整类写入）

- **前置状态**：REFRIGERANTE 20 道有序 0100…0119。
- **操作过程**：用与 UI 相同的「整份可见 id + 绝对下标」语义：交换 0↔1（第 1 页）、再交换 10↔11（第 2 页页内 0↔1）；每次查库后恢复。
- **预期结果**：仅对应两道对调；另一页相对顺序不变；仍写回 20 个 id（非整页 10 个）。
- **标签**：【已验证】pass（API+DB；浏览器键盘拖 Space 会误导航，未用实拖）

### 场景 5：搜索无结果无翻页条

- **前置状态**：任意。
- **操作过程**：搜索 `zzz_no_match_xyz`。
- **预期结果**：空态；无页码条。
- **标签**：【已验证】pass

### 场景 6：回归 — 推荐 tab 再回菜品

- **操作过程**：切 Recomendados → 再切 Pratos。
- **预期结果**：tab URL/内容正常。
- **标签**：【已验证】pass
