# 本次改动业务场景测试报告：员工按菜分单「分单结果」手机端可展开已分菜品

日期：2026-10-10
分支：`feat/staff-byitem-mobile-share-detail`
UAT 基址：`http://localhost:3003`（功能分支，`MESA_NEXT_DIST_DIR=.next-uat`；非 `:3000`）；另用 iOS 模拟器（iPhone 15 Pro Safari）复核

## 1. 本次修改

- **内容**：员工结账页按菜分单模式下，手机宽度（<md）的「分单结果」每个人名字左侧新增 ▸/▾，点开只读列出此人已分的菜行（菜名、`数量 × 单价 = 金额`、已收标记）。桌面（≥md）不显示，原有「待分池 | 当前份额」并排布局不变。
- **文件**：`BillSplitPanel.tsx`（可选 `rowDetail`）/ `StaffByItemSplitWorkbench.tsx`（抽出 `StaffByItemShareIdentity`，新增只读 `StaffByItemPersonShareSummary`）/ `StaffCheckoutSplitEditor.tsx`（仅按菜模式传入）
- **角色 / 页面**：员工（前台）· 手机 · `/dashboard/checkout` 详情 · 按菜
- **不动**：金额计算、收款、分单持久化、顾客账单页、均摊、整桌

## 2. 核心业务规则

1. 【本次新增】展开内容与右侧「当前份额」同一数据来源（`staffByItemPersonShares`），不另算金额。
2. 【本次新增】桌面宽度不出现展开控件（`md:hidden`）。
3. 【已实现】点名字 = 改名；展开只能点独立箭头，两者互不触发。
4. 【已实现】已收款份额带「已收」标记，只读。

## 3. 详细测试场景

### 场景 1：手机上查看某人已分菜品
- **前置**：白云店 VIP999 开台；自助餐成人 ×2、Cartuxa ×3、Pera Manca ×2、Cartuxa ×1；方案：小王（自助餐 1A + Cartuxa + Pera Manca，已收现金 €149.90）、小李（自助餐 1A + Cartuxa + Cartuxa，未收 €89.85）。
- **操作**：员工手机打开结账详情 → 滑到「分单结果」→ 点小王的 ▸。
- **预期**：展开 3 行，每行带「已收」，合计与 €149.90 一致；点 ▾ 收起。
- **数据验证**：展开内容 = 当前份额面板同一份数据。

### 场景 2：点名字改名不误触展开
- **操作**：手机点「客人 1」名字。 **预期**：出现改名输入框，`aria-expanded` 仍为 false。

### 场景 3：展开中删除一道菜
- **操作**：展开后在「当前份额」点某行「移回剩余」。 **预期**：展开内容和金额同步（€54.90 → €19.95）。

### 场景 4：收款后
- **操作**：现金收款当前人。 **预期**：分单结果出现「已收款」徽标，展开行带「· 已收」。

### 场景 5：桌面宽度回归
- **操作**：1024 宽度打开同一页（含展开状态切回桌面）。 **预期**：箭头、展开块 `display:none`，行文字与改前一致。

### 场景 6：整桌 / 均摊回归
- **操作**：新开桌，分别看整桌与均摊的「分单结果」行。 **预期**：与未改动代码逐坐标相同，无箭头。

- 【已验证】场景 2、3、4、5。
- 【已验证】场景 6：新旧代码两侧「分单结果」行坐标逐项相同（box 385,36,586,78；行 386,37,584,76），toggles=0。

## 5. 风险与待确认

- 手机窄屏下该行已有名字 / 已收徽标 / 金额 / 收款按钮，再加箭头可能略挤：375px 与模拟器上观察正常，更窄屏未测。
- 展开状态只存在界面，刷新后收起（设计如此）。
