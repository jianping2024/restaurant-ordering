# 本次改动业务场景测试报告：分组列表外卖标记去重

日期：2026-10-29  
分支：`fix/table-groups-takeaway-list-mark`

## 1. 本次修改

- **内容**：后台「桌台 → 分组」列表里，外卖组不再同时显示名前图标 + 黄色「外卖组」文字标签；改为「组名 → N 张桌 → 🥡」。
- **文件**：`apps/web/src/components/dashboard/TableGroupsManager.tsx`
- **角色 / 页面**：店主（或有桌台设置权限的员工）→ `/dashboard/tables` → 分组 Tab
- **流程**：纯列表展示；不改 `is_takeaway` 存取、编辑弹窗勾选、开台/点餐逻辑

## 2. 核心业务规则

1. 【本次新增】列表行上「是否外卖组」的视觉标记只有一种：桌数 pill 后面的 🥡（外卖点餐功能开启且该组 `is_takeaway`）。
2. 【已实现】组是否外卖仍只看库里的 `is_takeaway`；编辑弹窗勾选不变。
3. 【已实现】非外卖组、或外卖点餐功能关闭时，列表不显示 🥡。
4. 不变量：改展示不改变组成员、排序、开台渠道。

## 3. 详细测试场景

### 场景 1：外卖组列表展示（正常）

- **前置状态**：店主登录；外卖点餐功能开；已有一组勾选为外卖组（组名可叫「外卖组」）。
- **操作过程**：打开 `/dashboard/tables` → 分组 Tab，看该行标题带。
- **预期结果**：顺序为「组名 · N 张桌 · 🥡」；没有黄色「外卖组」文字 pill。
- **数据验证**：组成员 chips、桌数与改前一致；库 `is_takeaway` 不变。
- **异常恢复**：刷新页面后展示仍同上。

### 场景 2：普通分组无外卖标记（回归）

- **前置状态**：同页有非外卖组（如 VIP1）。
- **操作过程**：看非外卖组行。
- **预期结果**：只有组名 + 桌数；无 🥡、无黄标。
- **数据验证**：无。
- **异常恢复**：无。

### 场景 3：编辑弹窗仍可认外卖组（回归）

- **前置状态**：打开外卖组的「编辑」。
- **操作过程**：看「外卖组」勾选框。
- **预期结果**：仍勾选；说明文案仍在；取消勾选并保存后列表该行无 🥡。
- **数据验证**：保存后 `is_takeaway` 与勾选一致（若执行取消勾选需再勾回以免脏数据）。
- **异常恢复**：关弹窗不保存 → 列表不变。

### 场景 4：操作顺序 / 并发 / 多终端

- **不适用原因**：本次只改列表标题带排版，不涉及写冲突；不测并发与跨终端互相影响。

### 场景 5：功能关闭时无图标

- **前置状态**：【待核实】当前 UAT 店外卖点餐是否开启——若已开，本场景用「非外卖组」代替验证「无 🥡」。
- **操作过程 / 预期**：外卖点餐关时，即使历史组有 `is_takeaway`，列表也不显示图标（代码条件：`takeawayOrderingEnabled && row.is_takeaway`）。
- **标注**：若本轮未关功能开关，标【未验证】。
