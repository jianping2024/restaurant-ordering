# 本次改动业务场景测试报告 · 详情进页套餐不闪

分支 `fix/detail-occupied-boot-buffet-seed`。  
UAT 基址：`http://localhost:3002`（`MESA_NEXT_DIST_DIR=.next-uat`）。

## 1. 本次修改

- 楼面桌卡摘要增加当前套餐 id（`currentBuffetId`）。
- 从楼面进已开台详情时，boot 带上该桌已知套餐与人数，第一帧按已锁定画，不再先出现多套餐可选。
- 已开台但暂时还没有当前套餐 id 时，套餐区只显示加载骨架，不画可选列表。
- 空桌开台仍可选多套餐。

涉及：`waiter-board-snapshot.ts`、`waiter-table-detail-scope.ts`、`WaiterTableDetail.tsx`、相关测试与 sole。

## 2. 核心业务规则

1. 开台确认后套餐固定；进详情第一帧也不能露出第二套可选。
2. 当前套餐仍只认订单里的当前套餐行（boot 种子也是同一套读法）。
3. 空桌开台可选多套餐，不受影响。

## 3. 详细测试场景

### 场景 1：已开台桌进详情不闪第二套餐（正常）

- **前置状态**：白云前台已登录；A-01 已开台 Buffet livre、A2 C2。
- **操作过程**：打开详情 URL，连续采样页面套餐 radio 数量约 3 秒。
- **预期结果**：全程最多 1 个 radio；正文不含「UAT 第二套餐」；最终只显示 Buffet livre（禁用）+ 人数 2/2。
- **数据验证**：楼面 board 摘要 `currentBuffetId` 有值。
- **异常恢复**：刷新详情仍锁同一套。

### 场景 2：空桌开台仍能选两套（回归）

- **前置状态**：A-06 空闲。
- **操作过程**：点 Abrir 打开开台弹窗。
- **预期结果**：可见 Buffet livre 与 UAT 第二套餐两个选项。
- **数据验证**：取消即可，桌仍空。

### 场景 3：改人数仍锁套餐（回归）

- **前置状态**：场景 1 详情已打开。
- **操作过程**：成人 −/+（若 UI 可点）。
- **预期结果**：套餐仍为 Buffet livre，不可换套餐。
- **备注**：本轮详情页有「继续点餐」弹层干扰，人数点按标【未验证】；锁套餐 UI 与 board 种子已验证。

## 4. 实际测试结果

- 场景 1【已验证】采样 63 次：`maxRadios=1`，`anyUat=false`；定稿仅 Buffet livre disabled。
- 场景 2【已验证】A-06 开台弹窗两套可选；已取消。
- 场景 3【未验证】继续点餐弹层挡住人数操作。
